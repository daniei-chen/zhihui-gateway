# Trae HTTPS 回调到达实验

目的：用户本人在官方页面授权后，确认该页面是否能跳回智汇域名并由 Linux 接收。
**仅实验，不兑换授权码、不导入账号、不自动接入号池。** 不能据此声称供应商注册允许自定义回调或完整 OAuth 兼容。

## 固定边界

- 独立标准库服务监听 Linux `127.0.0.1:17388`，Nginx 仅转发 `/trae-callback-test/`，不开放公网端口。
- 需要已有智汇本人会话。用户点击 POST 后才向 Manager 创建常规 Trae 授权；已有等待／未知授权不覆盖。
- 保留原链接的客户端、trace、PKCE challenge，只把回调目标替换为固定同源路径加随机能力。
- 同浏览器 HttpOnly/Secure/Lax 测试 cookie、本人 Manager 会话、所有者与授权代次、trace、有限格式和有效期共同核验。
- 回调中授权码／userInfo 仅在内存检查后丢弃，不兑换、不落盘、不反射、不写访问日志。
- 页面展示的是“匹配回调到达”，不是“真实授权码有效／账号入池”。测试结束需点击释放授权；进程重启不恢复测试能力。

## 部署约束

Nginx 专属位置必须关闭 access_log、查询串错误输出、缓存与代理临时文件；不得转给会记录原始回调 URL 的 Uvicorn。
测试进程无生产数据目录、引擎网络凭据与写权限。只允许固定 Manager 回环接口，不提供 finish/exchange 方法。
systemd 使用独立动态用户、零 capabilities、只读系统、内存与进程限制，限定测试运行时长。
配置修改必须持有现有发布与备份锁，核对原字节、保存回执、nginx -t 与平滑 reload；不改 DNS、登录页或现有授权链路。

本地测试：`python -m unittest discover -s tools/trae-callback-probe -p test_server.py -v`。
测试全部使用合成 Manager 和本机临时端口，不向官方站点发送登录、验证码或授权请求。

## 本次实验的限制与回退

- 使用现有 `zhihui.kaogong.art` 的独立子路径，不需要新增 DNS；同源也保留现有登录 cookie。
- Nginx 正常匹配实验路径后的访问／错误日志均关闭。超长、畸形请求若在 Nginx 解析阶段被拒绝，仍受全站的底层日志策略约束；本实验不把关闭全站日志作为解决办法。
- 进程不随开机启用，最多运行两天后停止。会话仅驻内存，普通测试授权约五分钟有效；不要与控制台另一 Trae 授权同时进行。
- 回退命令：`sudo /usr/bin/python3 -I -B /opt/zhihui-release/experiments/trae-callback-20261030-r2/rollback_remote.py`。
- 回退核对实验前后精确 Nginx 字节，只撤销本次隔离位置／限流配置并停止测试进程。若配置后来发生其他变更，拒绝覆盖，须人工合并；不恢复业务数据库或用户文件。
- 测试成功后点击“结束测试并释放授权”，回控制台重新发起正常授权。官方返回成功不等于兑换成功，自定义域名仍可能被官方安全策略拒绝。
