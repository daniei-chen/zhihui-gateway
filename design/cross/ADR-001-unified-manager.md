# ADR-001：三平台统一到一个 Manager

日期：2026-10-24。状态：目标架构与迁移约束；尚未完成控制面合并，未部署。

## 结论与边界

WorkBuddy、Qoder、Trae 可以共用一个 Manager。统一产品入口、身份与权限、公开推理密钥、预算账本、任务记录、错误契约、审计、监控和发布生命周期。三个引擎通过独立适配器接入，保留各自的账号协议、状态获取、模型映射、流格式和计费行为。

“一个 Manager”首先指单一控制面和业务权威，并不要求三个引擎与控制面共用一个进程。是否进一步合并 QTG 进程，以耦合消除、兼容性与隔离演练为依据，不能靠拷贝路由文件直接拼接。

本决策回应用户关于三者合成一个 Manager 的问题，不能用来跳过原 T00–T03、K01–K52 的验收，也不构成生产部署结果。

## 当前真实结构

候选树中 `manager/server` 承担 Manager，`qtg/app/qtg` 承担 QTG，`src/three-platform/web` 承担共用前端。Manager 中的身份、公开密钥与预算仍为权威；QTG 以签名断言获取主体，管理令牌保留原 scope 上限。候选 Nginx 按平台分发部分控制端点，因此目前仍是两个控制面进程。

`qtg/app/qtg/adapters/workbuddy.py` 仍读取 Manager SQLite 并读取引擎文件；`adapters/trae2.py` 仍读引擎 SQLite。这些是需要治理的存储耦合，不应成为合并后的公开契约。`src/three-platform/server` 是历史参考，不得混进正式运行包。

## 目标组件与唯一权威

| 组件 | 责任 | 约束 |
| --- | --- | --- |
| 统一控制面 Manager | 登录、主体、RBAC、密钥、平台授权、预算、管理 API、任务调度、审计 | 对同一状态只存在一个写入者；用户操作每次在服务端鉴权 |
| WorkBuddy/Qoder/Trae 适配器 | 账号、模型、健康、平台操作、流与用量规范化 | 明确能力表；不支持的操作返回稳定错误，不假成功 |
| 数据面入口 | 平台选择、准入、请求生命周期、流转发、取消、未知消耗保留 | 既有密钥与路径保持兼容；发生未知消耗不能释放预算 |
| 引擎服务 | 对接各自上游、持有各自账号运行态 | 独立健康、超时、并发、熔断和重启边界 |
| 前端 | 同一导航与平台选择；按服务器能力展示操作 | 页面显示与按钮隐藏均不能替代后端权限 |

平台适配器最小契约：`capabilities`、`health`、`accounts.list`、`accounts.action`、`models.list`、`settings.read/update`、`inference`、`usage.normalize`。每个操作显式声明支持平台、所需权限、超时、幂等策略、秘密字段、结果版本和审计事件。引擎没有的功能不通过空数组或成功 toast 冒充实现。

## 迁移顺序与退出条件

| 阶段 | 实施内容 | 退出条件 |
| --- | --- | --- |
| U0 固定证据 | 统一候选哈希、路由与角色契约、配置快照、引擎能力表、数据库 schema 版本 | 同一候选能重建；旧/新路由的语义差异逐项登记 |
| U1 权威收敛 | 共用 Manager 登录与密钥；签名身份桥接；平台授权和 scopes 统一 | 三平台×会话/令牌的真实链路通过；旧 Cookie/密钥/降权/吊销验证；不批量换钥匙 |
| U2 适配器与读取契约 | 将 QTG 平台能力做成边界模块；用版本化、分页、鉴权的只读 API 替代 Manager 跨进程 SQLite 查询 | 聚合不依赖 Manager 表结构；断连/不兼容可见；数据源、更新时间、时区与单位明确 |
| U3 控制端点收敛 | Manager 提供统一 `/api`；QTG 旧路径作为可观测兼容代理；后台任务与审计统一归属 | 213 条历史路由及新增候选路由均有去向；不双执行签到/清理/更新；页面与持久化结果一致 |
| U4 进程收敛评估 | 将可移植适配器在 Manager 中运行，或保留独立 worker；移除已无职责的 QTG 控制服务 | 不再有活跃调用、任务、会话、恢复依赖；并发/资源/故障与回退演练通过后才停旧服务 |

U1 已有部分候选代码与隔离链路证据，U2–U4 不能据此标记完成。合并前必须完成当前回归和逐页发现问题，避免把未清理缺陷带入新目录。

## 最小停机与一致性

1. 在线运行时、静态资源、配置、状态分别管理，候选在独立目录构建。旧前端 chunk 在保留期内继续可取。
2. 管理面与各引擎分别发布，一次只切一个平台；控制面变更不应顺带重启全部引擎。
3. 使用 expand/contract 兼容数据库迁移。保留新增字段和审计记录；代码回退不得恢复旧 live DB 或撤销已发生的密钥吊销。
4. SQLite Manager 保持单写入者。接替必须先排空、确认旧写入者退出与所有权移交，再开放新写入者；不能以两个进程同时共享 live DB 冒充无停机切换。
5. 对已准入长流、取消、未知消耗、拒绝新请求分别计量。当前已有长流排空证据，准入交接中断仍未测出可承诺数值；不得宣称零停机。
6. 如目标中断时间不能满足，先给出测量证据，再选择队列/入口重试或进一步的状态架构调整；不得自动重试已被上游接收的请求。

## 必须保留的验收证据

三平台真实 UI→API→持久化→重新读取；能力不可用和权限拒绝两类结果；角色和 scope 上限；原有调用路径、SDK、密钥、模型别名与 SSE；预算及消耗对账；长流排空和接替；单平台故障隔离；旧资源可取；完整恢复；统一进程前后内存/FD/CPU/并发基线；每阶段兼容回退和遗留服务去依赖记录。

合并目录、增加一个统一首页或全部测试在不同版本各自通过，都不能替代以上证据。
