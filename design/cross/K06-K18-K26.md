## K06 平台选择不等于平台授权

**现状**
- 前端通过 `X-QTG-Platform` 表达目标平台；Nginx 按该头把 `/api/` 分流到 QTG 或 Manager；
- Manager 侧用路径前缀（`/v1`、`/qoder/v1`、`/trae/v1`）与模型前缀选上游；
- 没有统一的"主体能否访问目标平台"策略：header、路径、模型前缀三者冲突时规则不明确。

**风险**：客户端可以表达"我要走 trae"，但服务端没有独立的授权判断；迁移后的 QTG 旧 key 带 `platforms`，
而 Manager 新建 key 没有平台字段 → 两套语义。

**设计**
1. 定义"生效平台"的唯一来源，优先级固定为：显式路径 > 请求头 > 模型前缀 > 默认；
2. 在 `keysvc.validate` 里增加平台判定：
   - 旧 QTG key：用 `legacy_platforms`（迁移台账里已有）；
   - Manager key：平台由 `realm` + `models` 推导，或显式新增 `platforms` 列（后续任务）；
   - 不匹配 → 明确 403（不是静默改路由）；
3. 未知平台值（不在 qoder/trae/workbuddy）→ 拒绝，不回落到默认；
4. 审计与日志记录"请求表达的平台"与"实际路由的平台"，两者不一致时告警。

**验收**：同一把 key 在三个平台的允许/拒绝矩阵可复跑；伪造头不改变授权结果。

## K18 路径包含性与隐式重启

**现状**
- QTG `clear-cooling` 用 `file:path` 拼接 JSON 路径（`file:<path>` 形态）；
- 沙箱会限制写入，异常分支可能触发 `qoder-proxy` 重启；
- 尚未证明存在公网任意文件写，但拼接方式本身不可接受。

**设计**
1. 输入改为**白名单 ID**（账号 uid），不接受路径参数；
2. 所有文件路径用 `Path.resolve()` 后做 `is_relative_to(base)` 包含性校验，拒绝符号链接越界；
3. 业务失败（找不到账号、冷却不存在）不得触发无关容器重启；重启只能是运维显式动作；
4. 测试：`../`、URL 编码、Unicode 归一化、符号链接、大小写、NUL 字节。

## K26 只读直连耦合

**现状**
- QTG 直读 Manager SQLite（`wb_db` 配置）与 schema，用于聚合统计；
- 既有 Store 的 sqlite 连接关闭方式需要修（长事务/连接泄漏）；
- `mode=ro` 本身不等于数据库损坏，但跨服务直读 schema 是契约耦合。

**设计**
1. 先加**schema 版本探测**：QTG 启动时读 Manager 的 `user_version`/迁移表，版本不兼容则只读降级并告警；
2. 中期把统计读取迁到 Manager 的只读 API 或只读快照视图（`GET /api/stats/aggregate`）；
3. 连接生命周期：每次查询短连接 + `try/finally` 关闭，禁止跨请求持有；
4. 直读期间限制：只允许 `SELECT`，设置 `PRAGMA query_only=1`、`busy_timeout`，不碰 WAL 写入。

**验收**：Manager 升级 schema 后 QTG 不崩（降级而不是 500）；QTG 重启不产生孤儿连接。
