## 1.2.0 · 稳定性大版本

**本次构建：`v1.2.0+local.20261109.21`**

这一版不新增功能，把此前二十次修复累积成一个正式里程碑。所有改动均经过完整隔离门禁（4974 项通过、0 项失败）、Ed25519 签名与可信预检，并已完成生产切换与回滚演练。

### 稳定性

- 批量签到、刷新额度、领取补偿、核对令牌四个批量入口，单个账号出错不再拖垮整批。此前的表现是整批返回服务器错误。
- 上游输出超限时返回明确的错误类型，不再混作「传输错误」；长回答被截断的问题同时通过提高输出上限解决。
- 门户账本繁忙时返回可重试的提示，而不是通用服务器错误。
- 客户端中途取消后留下的未决冻结，随例行对账自动释放，不再依赖服务重启。

### 账务

- 回执缺少供应商用量时不再回落成用户扣费金额，避免把用户付的钱当成平台成本。
- 用户账本与主库的一致性检查改为独立自检、分钟级执行，不再依附于每日备份；备份失败时依然会检查。
- 新增账目缺失的检出：某个用户只有消费记录、完全没有发放与流水时会被记入运行日志。

### 账号与任务

- 三平台账号「冷却中」的判定改为要求冷却到期时间确实在未来。此前已到期的时刻也会被当成仍在冷却，实测 48 个账号中有 28 个被永久误标。
- 随机签到的未确认状态增加超期出口，长期卡住的任务会自动恢复重试（实测解除一次持续 8.8 天的死锁）。
- 每日定时任务的失败写入审计记录，异常日志提升到错误级别。
- 单账号签到按平台分别声明：Trae 引擎只支持批量签到，面板不再统一显示为可用。

### 可观测性

- 非流式请求的首字节耗时也会被记录，排查变慢时不再只有流式样本。
- 账目缺失提示改为只在情况变化时记录一次，避免重复日志淹没真正需要注意的信息。
- 计划设置的查询会如实返回已保存状态，不再固定显示「未启用」。

### 安全

- 复核确认网关进程以非特权账号运行、且不持有任何能力位，权限分离由启动链保证。
- 启动链源码纳入版本留存，便于追溯。

完整历史见 [更新日志](CHANGELOG.md)。

## 看得清，也用得顺

<img src="docs/images/dashboard.png" alt="隔离合成数据仪表盘" width="100%" />

| 你在找什么 | 界面会告诉你 |
| :--- | :--- |
| 账号还能不能用 | 在线 / 冷却中 / 已过期 / 已停用，冷却剩余时间与限流模型分开呈现 |
| 额度还剩多少 | 积分余额、今日用量、到期提醒；未知不当零 |
| 请求为什么失败 | 错误族分类、上游状态、可复制的请求编号 |
| 钱花在哪 | 按密钥、模型、时间的用量与成本；供应商成本未知时明确标注 |

## 统一入口，各有其路

```text
客户端 ──► 智汇网关 ──► WorkBuddy / Qoder / Trae 引擎 ──► 上游
            │
            └── 密钥、配额、账本、审计
```

三条路径各自独立授权，互不串用。同一把密钥可以按模型白名单与 IP 规则限制到具体范围。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/v1/chat/completions` | Chat 兼容调用 |
| POST | `/v1/responses` | 有边界的 Responses 适配 |
| POST | `/v1/messages` | Messages 适配 |
| GET | `/v1/models` | 当前授权范围的模型列表 |
| GET | `/readyz` | 有界缓存的就绪结果，不发推理探测 |

## 把支持与不支持都讲清楚

**支持**：OpenAI 兼容的 Chat / Responses / Messages 三种协议、流式与非流式、多平台账号池、按密钥的配额与白名单、账本与审计留痕。

**不支持**：持久会话、后台任务、strict 工具 schema 保证。不支持的语义会在消耗上游配额之前明确拒绝，而不是静默降级。

**账务真实性**：供应商用量未知与用户钱包挂起分别表达，不从截断日志重建终身消费，不重写不可变事件。核对页不提供清零按钮；代码回滚不恢复旧业务数据库。
