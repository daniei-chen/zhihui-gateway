# 缓存指标：请求命中与 Token 缓存占比

状态：本地待审候选，尚未部署。

## 页面主值：请求命中率

`cache_hit_requests / cache_observed_requests`

- 分子：已报告有效缓存用量、且 `cache_hit_tokens > 0` 的推理请求数。
- 分母：在所选时间、版本及维度内，命中与未命中字段均为非负整数，且二者至少一项大于 0 的已记录推理请求数。
- 只统计 OpenAI、Anthropic、Responses 推理协议，不把管理请求纳入分母。
- 一个请求只有部分输入命中，也算一次请求命中。这不是“整段上下文全部命中率”。
- 不依赖 HTTP 成功状态，只要已经收到有效缓存报告就保留事实；错误或取消且没有缓存报告的请求不算未命中。
- 样本来自保留中的请求日志。没有请求级证据时为 `null`，不能从每日 Token 合计倒推请求数。

按密钥、按模型都使用该定义。WorkBuddy HTTP / SQLite 读通道提供相同新增字段；Qoder / Trae 的按密钥保留日志视图同步提供。只有模型合计、没有请求级缓存证据的上游仍显示未知。

## 页面次值：Token 缓存占比

`cache_hit_tokens / (cache_hit_tokens + cache_miss_tokens)`

该值描述输入 Token 中命中缓存的比例，输出 Token 不进入分母。它用于观察缓存覆盖程度，与“至少命中过一次的请求比例”不是同一个问题，不应相互替代或混用标签。

## 接口兼容

- 既有 `cache_hit_rate` 保留 Token 口径，避免现有接口调用方在没有版本提示时被静默改变语义。
- 新增 `cache_request_hit_rate`、`cache_hit_requests`、`cache_observed_requests`，页面主值明确改用新增计数。
- 缺失样本主值显示 `—`，不能回退为旧 Token 比率。页面保持一位小数；样本量在提示中可查。
- 历史请求、`usage_daily`、API 密钥配额与费用均不改写。本次展示变更无需业务数据库迁移。

## 验收案例

请求 A：1 命中 Token、999 未命中；请求 B：0 命中、1 未命中。

- 请求命中率：1 / 2 = 50%。
- Token 缓存占比：1 / 1001，约 0.1%。

两个值可以同时成立，不能为了数值接近或更好看而相互代替。真实缓存覆盖是否改善，要继续观察 Token 次值、会话路由与新增请求，不能仅凭主值变大宣称修复成功。
