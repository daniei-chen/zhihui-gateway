# 安全审查与整改记录

2026-10 对生产实例做了一次全量审计（代码、日志、接口、发布链、计费口径）。本文记录
**已修复的问题与验证方式**，以及**仍然存在的边界**。不提供可直接利用的复现细节。

## 已修复

### 1. 平台控制面的写操作缺授权（高危）

qtgcore 的处理函数签名里没有任何授权依赖，而同路径的管理端原生实现都有管理员校验。
后果：任意一个已登录的低权限会话，加上一个平台请求头，就能对真实账号执行签到、改配置、
删账号这类写操作。

**修复**：在平台路由的中间件里加统一闸门 —— 写方法必须同时满足「Cookie 身份 role=admin」
且「不是服务令牌」。读方法行为不变。

**验证**：viewer 会话对 8 条写路径逐一请求，全部 403；管理员会话与旧行为一致。

### 2. 平台控制面完全不在签名清单里（高危）

发布清单生成于 10-26，而 `server/qtgcore/` 是 10-27 合并进来的。清单工具的重建模式
**只更新已有条目的哈希、不新增文件**，于是整个目录从未受门禁保护 —— 改它不需要签名，
启动也不会校验。

**修复**：重新生成清单，把 qtgcore 全部纳入。受保护文件数 323 → 357。

**验证**：独立用 `sha256sum -c` 复核 357/357 全部匹配；`openssl pkeyutl` 验签通过；
故意改一个字节后 preflight 拒绝启动（退出码 4）。

### 3. 不存在的 API 路径返回 SPA 页面

单页应用的兜底路由排在 `/api` 匹配之前，未实现的管理接口返回 404 + 11 KB 的 HTML。
调用方按 JSON 解析会得到难懂的解析错误，而不是「这个接口不存在」。

**修复**：在 SPA 兜底之前拦截 `/api`，统一返回 JSON 404。

### 4. 路径前缀用 `startswith` 匹配，边界越界

`/api/logs` 这样的前缀会让 `/api/logsXXX` 也命中，导致「哪些路径会进平台控制面」
无法静态推断 —— 既增加攻击面，也让审计困难。

**修复**：改为按路径段边界匹配（完全相同，或以 `前缀/` 开头）。

### 5. 上游错误码被吞成 200

`/v1/messages` 在上游返回 4xx/5xx 时，仍把响应包成 200 返回给下游。下游的重试逻辑、
熔断、监控全部失效 —— 明明是上游 429，看起来是「成功的空响应」。

**修复**：上游状态码 ≥400 时读取并关闭上游响应，用真实状态码回错。

### 6. 预算预留的 `unknown` 状态永久阻塞配额

有配额密钥的限制是「只允许 1 个请求在途」，而 `unknown`（上游没回用量、等人工核对）
也被计入在途。实测积压 120–190 条，最老的停在 10-24。后果：一旦给密钥设配额，之后
**每一个**请求都返回 `budget_pending`，且不会自愈。

**修复**：只把 15 分钟内的 `unknown` 视为在途，更老的交给对账任务；与「只有进行中的
请求才该阻塞新请求」的原本意图一致。历史积压走正规核对通道（`budget.resolve`，
零额度结算、逐条落审计）归档，共 159 条，无账务影响。

### 7. 三处计费口径对不上

「已执行额度」「孤儿额度」「明细合计」三处各算各的，差额无法解释。

**修复**：统一口径后三者精确相等（实测 52817.56 + 2934.02 = 55751.58）。

### 8. 匿名 4xx 污染不可删的审计链

审计链有禁删触发器，而匿名扫描产生的 4xx 也在写链 —— 24 小时内匿名 4xx 占 90.2%。
链会被无关噪音迅速撑大，真正的管理动作淹没其中。

**修复**：匿名 4xx 不再写入审计链。

### 9. 其余

- 登录接口加限流（PBKDF2 属 CPU 放大面）。
- 内部校验端点只允许 nginx 内部子请求，外部不可直达。
- 管理面适配器/授权路径对外返回 404，不暴露端点是否存在。
- 服务单元限制内存上限，避免异常时吃光整机。
- 备份脚本原先漏掉 13 个密钥文件，已补齐并加文件数自检。

## 仍然存在的边界

这些问题**没有被修掉**，是设计上的取舍或客观条件限制，列出来避免误解：

| 边界 | 说明 |
|---|---|
| 私钥在本机 | 能拿到本机 root 的人就能签发布包。高保障需要私钥离线或 HSM。 |
| 门禁防的是磁盘篡改 | 防不住「有 root 的人重新签一份合法包」。 |
| 备份不是真异地 | 当前远端目录与生产同机。真正的异地需要对象存储或独立远端凭据。 |
| 平台数据面缺少真实流量验证 | Qoder / Trae 的控制面与协议适配是通的，但数据面尚未有持续的线上调用量。 |
| 首字延迟依赖容器日志 | 上游不在本机或未挂 `docker.sock` 时，「实际调用账号」一列取不到值。 |
