# 一份源码，三种身份

智汇产品的唯一源码与升级来源是 [`daniei-chen/zhihui-gateway`](https://github.com/daniei-chen/zhihui-gateway)。
这不是模型供应商地址，也不是把 WorkBuddy、Qoder、Trae 引擎改成 GitHub 服务。

| 身份 | 本版约定 | 含义 |
| --- | --- | --- |
| 当前源码产品版本 | `1.2.68` | 补进程内存与线程数指标 ——长期跑会不会胀，此前只能等崩了才知道 |
| Manager 组件基线 | `v10.7.22+audit.20261029.2` | 继承源码的审计基线，不参与产品版本比较 |
| 源码与分发身份 | 输入源树 SHA256 与 Git commit SHA 分列 | 签名包绑定输入，公开分发提交在验收清单关联，不回写伪造先验提交 |

同一产品版本的部署可以使用独立构建标识，例如
`v1.2.68+build.20261114.1`。它只用于不可覆盖的发布目录、运行身份核验与回退，
不新增一条产品版本：界面和更新比较采用 `1.2.68`。部署时的 `.version`
与目录名一致，并受签名和完整测试回执覆盖；绝不覆盖已有发布目录。

这是产品版本归一，不是把旧组件版本当作产品的远端竞争版本。
历史发布目录、签名与回退证据保留原名；新版本比较在产品版本空间内进行。
旧的无仓库身份缓存不再用于新版本检测。

1.2.68 的功能、门禁与验收边界见仓库 [CHANGELOG](../CHANGELOG.md)、[上游复核](UPSTREAM-REVIEW-2026-11-14.md)、[线上审计](PRODUCTION-AUDIT-2026-11-14.md) 与 GitHub Release；更早文件保留原版本，只代表历史记录。源码拉取工具仍须提供匹配的完整提交 SHA；拉取不等于安装批准。旧网页覆盖安装已退役。

## 升级链路

```text
你的 GitHub 仓库
   │ 固定 commit / 经核对的 tag（不直接安装 main 最新状态）
   ▼
新源码工作目录 → 依赖锁 → 构建 → 隔离测试
   ▼
逐文件哈希 + Ed25519 签名 + 绑定输入与运行时的测试回执
   ▼
最低状态兼容检查 → 受控发布 → 运行身份与健康核验 → 记录版本与源码提交
```

`tools/repository_source.py` **只负责拉取固定源码，不负责安装或重启**：

```bash
python3 tools/repository_source.py \
  --commit <经审批的完整40位提交SHA> \
  --tag v0.0.3 \
  --destination /path/to/new/zhihui-source
```

它固定产品仓库，拒绝覆盖现有目录，核对 tag/commit/VERSION，且不接收任意仓库 URL。
拉取成功不等于产物可信或已部署；不能拿源码下载摘要代替受信签名。

## 三平台上游交接

v1.2.25 的 Qoder 与 Trae 数据面分别读取受保护的本机路由交接文件：
`/opt/workbuddy-manager/engine/var/qoder_gateway_base` 与
`/opt/workbuddy-manager/engine/var/trae_gateway_base`。缺失、非法或不安全的文件
会回退到签名版本中的可信默认端口；路由交接不包含凭据。
候选实例必须先在独立端口完成镜像摘要、运行身份、只读根文件系统和健康检查，再由受控发布器把稳定 relay 指向候选，最后用发布包内的工具原子写入 relay 地址：

```bash
python3 deploy/trae_route.py http://127.0.0.1:7867 \
  --route-file /opt/workbuddy-manager/engine/var/trae_gateway_base
```

Qoder 使用同一工具和校验合同，只需指定 /opt/workbuddy-manager/engine/var/qoder_gateway_base：
```bash
python3 deploy/trae_route.py http://127.0.0.1:8801 \
  --route-file /opt/workbuddy-manager/engine/var/qoder_gateway_base
```
工具拒绝公网地址、凭据、路径和非法端口；父目录必须已存在且不可被组或其他用户写入。root 发布时路由文件固定为 `root:10001`、`0640`，非 root 开发测试使用私有 `0600`。网关遇到缺失或不合规的路由文件会回到各平台的可信默认端口。路由文件只包含地址，不包含密钥；切换前后的健康、排空、账本和回退证据仍必须由受控发布器记录。

Manager 的不停机候选必须使用发布包内的 `deploy/workbuddy-web-helper.service`，并完整继承当前 serving 代的 admission 参数（容量、请求体预算、队列和密钥并发）；缺少任一参数会被共享 admission ledger 以 `shared_admission_policy_changed` 拒绝。relay 以 UID/GID `10001:10001`、只读状态运行，root 发布工具写出的路由文件合同为 `root:10001`、`0640`，不能把 root-only 的 `0600` 文件直接交给 relay。

## 回退不是时光倒流

回退代码/前端时不恢复旧账号、额度账本、设备授权和会话撤销状态。
必须检查数据库/接口向前兼容性，失败保留仍可能接收流量的实例，不能盲杀 helper。
角色与每日额度写入后，回退目标必须继续执行这些规则；旧版本仅能读取新表不等于安全可回退。
历史 `manager/.github` 和 `manager/deploy` 中的安装模板仅为继承组件参考，
不代表本机可信工具已被重新安装，也不应直接用于覆盖运行服务。

## 不夸大的边界

产品版本不是“所有审计项已关闭”的认证。真实供应商计量缺失仍记为未知；
没有付费端到端推理证据就不声称已完成供应商验收；本机加密备份不等于离机灾备。
前端来源为 reconstructed-source，新的 Git 提交不冒充复现历史原始提交。
新增管理能力、三平台授权边界与原生浏览器实验状态分别见
[授权合同](AUTHORIZATION.md)和[服务器代管浏览器](SERVER-ASSISTED-AUTH.md)。
