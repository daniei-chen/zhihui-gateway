# 账号出口线路（命名代理）

面板支持给**单个账号**绑定命名 HTTP/HTTPS 代理，让不同账号从不同出口 IP 访问上游。

## 为什么需要

上游对同 IP 的多账号并发比较敏感。把账号分散到不同出口线路，是降低风控触发概率的
常规做法。按账号绑定（而不是全局一个代理）才有意义 —— 全局代理只是换了个公网 IP，
账号之间仍然同源。

## 能力的边界

面板侧负责：

- 保存命名线路（名称 → 代理地址 / 认证信息）；
- 在账号详情里选择该账号走哪条线路；
- 在账号列表里显示当前绑定关系。

**聊天和上游后台任务要真正走这条线路，还需要 workbuddy2api 侧配套支持。**
面板不改上游一行代码，所以这里存在一个前提：上游版本需要能读取并使用这份绑定关系。
上游不支持时，绑定关系只是记录，实际流量仍走上游自己的出口。

判断方法：绑定线路后，从上游侧看该账号的出站 IP 是否变化。没变就是上游还没接。

## 配置位置

绑定关系与账号元数据存在一起（账号维度的附加信息），不写进上游的授权文件。
这样上游升级覆写授权文件时，绑定关系不会丢。

## 与 IP 管控的区别

容易混淆，说明一下：

| 功能 | 作用方向 | 管的是 |
|---|---|---|
| 账号出口线路 | **出站** | 我方以什么 IP 访问上游 |
| IP 白 / 黑名单、每密钥 IP 上限 | **入站** | 谁能访问我方 `/v1` |

两者互不相干。入站白名单再严，也不会改变出站 IP；出口线路再多，也不影响谁能调你的网关。
