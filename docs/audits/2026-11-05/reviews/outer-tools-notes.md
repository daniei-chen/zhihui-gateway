# Outer tools: full source review

Date: 2026-11-05. Reviewer: gateway audit agent. Baseline: `4c6b4cb8` plus the shared audit working tree. Scope: the 12 files in `outer-tools-reviewed.tsv`, 1,965 lines, each read in full. This was a read-only source review: none of these tools, candidate binaries, private engines, build steps, network requests, or native deployment commands were executed. Only this note and its review inventory were written.

No new, demonstrable current-runtime P0/P1 was identified. These files are offline checks, historical evidence reducers, candidate preparation tools, fixture regeneration, or artwork generation. They are not the Manager inference request path. Their output must retain the evidence boundaries below; source review does not validate their old claimed measurements or past executions.

## Findings that affect evidence quality

### OT-01 — Historical index variants are not isolated (P2, benchmark validity)

`tools/k25_log_index_bench.py:261–324` iterates `base`, `safe`, `rewrite`, then `harmful` on one connection. It creates each variant's indexes but never drops indexes from previous variants. `rewrite` happens to include the safe set, while `harmful` is not a superset of `rewrite`: the expression indexes and the unfilled-account index remain present. Its reported `entry['indexes']` contains only that variant's declared list. The recorded `harmful` plans and write cost therefore concern the union of accumulated indexes, not the reported independent set. The source's “subsequent variants are supersets” comment is false for the last variant.

The database is explicitly created under `tempfile.mkdtemp` and the destructive DELETE/reseed operations use that local connection. SQL arguments are bound; the dynamic clauses and DDL are fixed source constants. Cleanup closes the connection and removes the temporary tree. This is a methodology defect, not evidence of production data modification. `_new_db` uses the current base schema plus legacy `_migrate`, not the complete current migration runner, and the copied SQL shapes are not automatically checked against current routers. Historical K25 numbers must not be presented as new production latency measurements. The separately implemented and measured `tests/benchmarks/gateway_resources.py` in this audit is unaffected.

### OT-02 — Static container checks can overstate what they establish (P2, dormant/static tool)

`tools/audit_container_hardening.py:51–143` accepts any matching non-`root` USER instruction, including numeric `0` and a nonfinal build stage; it does not evaluate the final image user or Compose overrides. A `sha-` tag substring does not prove an immutable image digest or its relation to source/SBOM. Any nonempty `cap_add` passes, including unnecessarily powerful capabilities; the socket-mount check counts Docker socket presence positively. The COPY/ADD regex cannot prove absence of credentials copied through a broad source directory. An empty parsed services mapping skips the individual Compose checks rather than recording their absence. Informative `read_only` rows are included in the aggregate passed count despite their commentary saying they are informational.

At this checkout the configured `src/three-platform/Dockerfile` and `src/three-platform/docker-compose.yml` paths do not exist. The Dockerfile existence branch records a failure and returns nonzero, so the current missing path does not silently pass. The script itself lists runtime provenance, persistence, and actual mount behavior as unverified. Treat its rows as historical heuristics, never as an independent current deployment security gate.

### OT-03 — Configuration inventory can omit parse failures and is not an exhaustive contract gate (P2)

`tools/audit_config_inventory.py:66–70` catches a source SyntaxError into an indirect `__syntax_error__` entry, but `audit()` neither returns this entry nor includes it in `ok`; the later indirect-only projection retains schema names only. A broken source file can therefore disappear from this inventory without directly failing it. Computed environment names and aliased/attribute-based helper calls are also outside its literal AST recognizer. `dead_in_schema` and sensitive defaults are reported but not part of the failure predicate; this is narrower than the opening claim that all listed differences signal inconsistency. Registered direct readers and deploy-only variables are intentionally informational.

The script parses source rather than importing it and writes only an explicitly supplied report path. These limitations do not bypass the independent whole-tree syntax checks already used in this audit. Do not use this inventory alone as proof that all settings are consumed and all source files parse.

### OT-04 — Synthetic binary acceptance depends on external isolation and normal Python execution (P2, test-evidence scope)

`ops/workbuddy-ingress/acceptance.py` verifies the candidate SHA-256 and rejects a symlink at the binary leaf, creates temporary fixture credentials, binds its HTTP fixture to loopback, restricts the child's environment, and terminates/reaps the child in `finally`. It checks rejection before body reads, chunked size enforcement, streaming/nonstreaming output, held capacity, saturation, and capacity release against the fixture provider. These are useful bounded synthetic cases.

Most acceptance predicates are Python `assert` statements (`127–180`). Optimized Python (`-O` or `PYTHONOPTIMIZE`) removes them while success rows are still appended. No such optimized invocation was executed or found as the current release path in this review. The script does not create or inspect a network namespace: the required network-none container is an external precondition documented by the ingress bundle. `real_provider_calls: False` and `production_data_mounted: False` are fixed output declarations, not observations made by the script. They require independent container/network/mount evidence. Hashing a pathname and later executing it also assumes a stable trusted candidate directory. None of this is a review of the complete private engine.

### OT-05 — Namespace materialization has a narrow shape contract (P2, conditional local path hardening)

`tools/materialize_static_namespace.py:9–32` rejects symlinks/junctions at `out` and the build namespace leaf, validates BUILD_ID, requires one empty namespace, and refuses `--apply` when the signature marker exists. It does not check every parent: a symlink at `out/_next` can redirect `namespace.mkdir()` outside the intended export while both checked leaves pass. This requires a locally supplied malformed candidate tree and explicit `--apply`; no current runtime attacker-controlled invocation was established. Existing tests cover the leaf/shape/signature cases, not an `_next` parent symlink.

`check_archive` checks that the empty directory survives and that regular files are absent beneath it; it does not reject link members, traversal aliases, or every archive hazard. Its returned `scope` explicitly delegates full Flight/signature/publication verification to the trusted publisher. Keep that narrow contract; this helper is not a safe-extraction or signed-release verifier.

### OT-06 — Historical reports and fixture generators are not fresh verification

`tools/r4_summarize_readonly.py` confines the resolved capture directory to the task evidence subtree, reads captured results and local hashes, and runs only `git rev-parse`. It always reports `NOT_READY_INCOMPLETE_BASELINE`, with category gaps rather than silently approving a release. Several findings and “no production modification/raw secrets” fields are hardcoded historical assertions, not inferred from arbitrary new input. The fingerprint unchanged field is added after the initial assertion and is not subsequently asserted; missing PID/start fields can compare equal via `.get`. The tool republishes complete supplied records into `commands-index.json` and performs no redaction itself, so sanitized input remains a caller obligation. Child output symlinks are not independently rejected. This is a trusted local evidence reducer, not an executable production safety monitor; old task paths and local artifact references also make it environment-specific.

`tools/regen_route_golden.py` imports the legacy `qtg/app` route auditor and writes both golden files at module import, without a `__main__` guard or an independent expected baseline. The current checkout no longer contains that legacy `qtg` tree. It is a historical fixture writer, not a passing assertion; rerunning a generator alone can bless a route regression unless the diff and duplicate groups are independently reviewed. No current runtime invocation was established.

`tools/check_product.py` checks useful cross-file identity, changelog, localization, icon hashes, preserved login content, and repository-contained README targets. Its predicates are also predominantly `assert`, so it is not a valid gate under optimized Python. Its scope is coherence of checked repository artifacts, not cryptographic trust in the release or runtime engine compatibility. It does not mutate source.

## Remaining files: preparation and artwork boundaries

`tools/audit_legacy_assets.py` scans repository text with fixed patterns, skips configured trees/files over 2 MB, truncates samples, writes only an optional report and always exits zero. It neither deletes assets nor runs the printed production commands. Its `RUNTIME_PREFIXES` classification is a heuristic: executable files under `ops/` or `tools/` become `doc_only` if no configured runtime prefix also references an asset. This cannot prove that an operational script is unused. Unreadable files are skipped, and `is_file`/reads can follow a file symlink outside the checkout; the trusted repository and human review assumptions remain necessary. The opening documentation correctly says that zero references are only a candidate list and require real process/configuration/traffic checks before deletion. Its exit zero denotes report completion, not safe deletion or zero findings.

`tools/prepare_workbuddy_ingress.py` and `tools/prepare_workbuddy_compression.py` require exact patch hashes and before/after file inventories. They reject lexical path traversal, drive/colon/backslash paths, case collisions, links/reparse points and hard-linked input files, and check source/destination ancestry. The destination must be new, is created mode 0700, and files use exclusive creation. The patch is applied with argument arrays, no shell, disabled Git global/system configuration and hooks, a check phase, and a 30-second timeout. Source bytes are rehashed during copy and again after applying to the destination. These are reconstruction tools; building, tests, signing and publication are explicitly still required. `lstat` followed by a separate read and parent checks are not race-proof against a concurrent same-user filesystem mutator; input size is not bounded. The review did not establish a remotely reachable writer or a current production execution path, so this is a trusted-workspace assumption, not a new runtime P1. Failed preparation can leave a partial new candidate but never overwrites an existing destination by design.

`tools/render_readme_assets.py` generates deterministic local SVG/text and an asset hash manifest. Text and dynamic attribute values are escaped; no script, remote fetch or runtime credential input is present. The `--check` branch compares bytes and fails on mismatch. README image paths are resolved and constrained to the repository. Its release date/test-count artwork is fixed historical copy, not recomputed from test evidence, and the manifest explicitly calls the preview historical/synthetic. Default invocation writes assets without a separate confirmation; version-derived filenames and destination ancestors assume a trusted checkout, while `check_product.py` separately validates the version format. This is a documentation generator, not a deployment or validation result source.

## Final cross-file authentication and accounting check

The immediately preceding independent review of `keysvc.claim_ip → gateway final dispatch → budget.forwarded → budget.settle / portalwallet.receipt / metering` found no new demonstrable P0/P1. Final dispatch re-resolves identity and checks permissions/routing before atomic IP binding and forwarding. The owned worker is joined on cancellation; cancellation checks bracket the claim/forward transition, and an already-persisted forwarding marker remains conservatively unknown when no completed result exists. The added paths did not introduce a portal-to-main nested write-lock inversion: preparation/forwarding finish one database transaction before entering the other, while `receipt` inside main settlement writes the main outbox only.

Live main settlement and wallet receipt now share `parse_usage` completeness and malformed checks. Invalid supplied values remain unknown, valid partial values are preserved, and legitimate zero/integer numeric strings retain their intended compatibility. The reviewed production `_record` call sites did not pass a separate credit override that defeats the supplied usage evidence. New usage tests call the real `_record`, require `state.recorded`, and inspect real temporary main/wallet/outbox rows; thus a fallback to spool cannot masquerade as a successful synchronous commit. The real-DB IP test proves same-process threaded contention; the isolated cancellation test uses mocks for surrounding dependencies and was not misrepresented as a full multi-process or ASGI proof. No tests were rerun for this final read-only confirmation, and the private complete engine remains outside available source coverage.
