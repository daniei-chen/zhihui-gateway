# Manager 启动配置 / v0.0.3

## 单一业务启动入口

2026-10-31 完成已部署 Manager 的配置归并。本地覆盖文件从18项减少为4项；
原始文件保留于受保护的运维事务目录，不删除历史记录。

| 位置 | 责任 |
| --- | --- |
| `workbuddy-web.service` | 网络依赖、业务环境、并发、超时、重启限速和基础沙箱 |
| `zz-steward.conf` | 与运行版本绑定的 SMTP / 模型密钥文件位置，不含明文秘密 |
| `zzzzz-writer-migration-gate.conf` | 发布维护期间持久拒绝启动 |
| `zzzzzz-writer-start.conf` | 唯一有效 ExecStart：主机可信签名校验、状态底线及单 writer 入口 |
| `zzzzzzz-writer-capability-recovery.conf` | 固定引导能力，仅为可信入口降权使用 |
| 两项 `systemd.control` 内存覆盖 | 原有 MemoryHigh / MemoryMax，未重设或搬移 |

基础单元不再包含另一份直接运行 Uvicorn 的命令。旧补丁脚本、旧端口、
旧 PYTHONPATH 和旧 ExecStartPre 已从生效配置移出。应用由主机可信入口
验证签名与角色/日配额底线后执行，不恢复运行时源码猴子补丁。

Manager 实际业务进程为 uid/gid10001，有效及 bounding capabilities 为0、
NoNewPrivs=1。附加 Docker 组尚未去除，因此不能把去 root 等同于已消除主机 root 风险；
白名单容器控制替代仍属独立审计项。

## 已验证什么

- 私有 Linux 宿主测试209项通过，覆盖精确旧文件哈希、部分重命名中断、
  正向/回退/再次正向、丢失协调锁、人工漂移与错误回退证据。
- 原生 systemd 的前后克隆单元均未启动。29项关键生效属性完全一致，
  包含环境、命令链、重启限速、超时、权限、沙箱、迁移闸门与内存上限。
- `systemd-analyze verify` 通过；独立有限身份夹具在真实沙箱中降权成功，
  不运行应用、不访问供应商、业务库、账号目录或邮件。
- 生产仅执行配置归并与 daemon-reload，不触发服务重启；PID保持不变，
  NRestarts=0。超过五分钟后 readiness200、采集和看门狗心跳仍更新。

这不是实际生产冷启动或代码回退演练。尚未完成的生产验收必须继续单独记录，
不能用克隆单元和身份夹具冒充真实停机恢复。

## 运维规则

1. 修改前固定主单元、四个发布覆盖和两项内存覆盖的哈希；
   按发布锁→备份锁的既定顺序取得协调权，拒绝未知覆盖。
2. 不编辑签名发布树，不移动或改名四个发布保护覆盖，不执行旧直接启动命令。
3. 验证实际 systemd 生效属性，而非仅对比文本；保留 OnFailure 旧链，
   待新通知入箱及完整替代验收后再退役。
4. 任何配置回退仅恢复该事务留存的确切单元文件；不恢复数据库、用户、账号、
   密钥、额度、撤销状态或账本，不回退角色/日额度底线。
5. 签名回退控制器继续负责版本相关的管家覆盖；不得把新 WB_* 环境变量
   强行留给不认识它们的旧兼容版本。

仓库中的旧安装模板不是当前生产可信入口的替代发布器，不能复制覆盖上述配置。
