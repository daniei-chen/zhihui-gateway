# 巡检不能建议一个规范禁止的操作（第 64 轮）

## 1. 上一轮留下的线索

第 63 轮末尾我 grep 了巡检里的魔数，找到两处：

```bash
229:        if [ "$age" -gt 86400 ]; then        # 24 小时，合理
369:    if [ -n "$free" ] && [ "$free" -gt 200 ]; then
```

第一处是对的 —— 「额度快照超过一天没更新」本来就是 24 小时。

第二处不对。

## 2. 那个 200 意味着什么

```bash
if [ -n "$free" ] && [ "$free" -gt 200 ]; then
    note "空闲页 $free 偏多，可考虑 VACUUM 回收空间"
else
    pass '碎片很少，无需 VACUUM'
fi
```

线上库的实际数字：

```
726M，185,629 页，空闲 0 页，journal=wal
```

**200 页 ÷ 185,629 页 = 0.108%。**

也就是说：**只要攒下 800 KB 的空闲页，巡检就会建议对一个 726 MB 的库做 VACUUM。**

## 3. 而规范第六节写着

> 对 700 MB 级数据库无脑 VACUUM —— 先看空闲页；**空闲页少说明没有碎片，
> VACUUM 只锁表不解决任何问题**

**0.108% 显然属于「空闲页少」。**

所以这条检查的实际情况是：**巡检在建议一件规范明令禁止的事。**

这比「数字不准」严重 —— 一个被信任的检查工具主动给出了会伤害系统的建议。

## 4. 改法：比例 + 代价

```bash
permille=$((free * 1000 / pages))
if [ "$permille" -ge 100 ]; then
    note "空闲页 $free/$pages（$((permille / 10)).$((permille % 10))%）—— 回收空间需要 VACUUM，它会全程锁表，挑低峰做"
else
    pass "碎片很少（空闲 $free/$pages，$((permille / 10)).$((permille % 10))%），VACUUM 不值得做"
fi
```

三个决定：

**① 判比例，不判绝对页数。** 同一段代码要同时对 7 MB 和 7 GB 的库成立，
绝对页数做不到。

**② 阈值 10%。** 低于这个比例，回收的空间不值得一次全表锁。

**③ 把代价写进文案。** 只说「可考虑 VACUUM」而不说「它会全程锁表」，
等于把决策成本藏起来 —— 而规范禁止它的原因正是那一下锁表。

**④ 兜底 `"$pages" -gt 0`。** `$((free * 1000 / pages))` 在 `pages` 为空时
直接报错。巡检是「一条命令给出全局结论」的那个命令，它自己不能崩。

## 5. 线上验证

```
== 数据库
  726M，185629 页，空闲 0 页，journal=wal
  ok    WAL 模式（读写不互相阻塞）
  ok    碎片很少（空闲 0/185629，0.0%），VACUUM 不值得做
  请求记录 370845 条，最早 2026-09-14
```

**改前**：`ok 碎片很少，无需 VACUUM`（结论对，但依据是错的 —— 是 `0 <= 200` 碰巧成立）

**改后**：`ok 碎片很少（空闲 0/185629，0.0%），VACUUM 不值得做`

**区别在于：改前的「对」是巧合，改后的「对」有依据。**

如果这个库哪天涨到 5,000 空闲页（仍是 2.7%，依然不该 VACUUM），
旧逻辑会说「偏多，可考虑 VACUUM」——错的。

## 8. 巡检里还剩哪些魔数

```bash
grep -nE '[^a-zA-Z_\"][0-9]{2,}' deploy/healthcheck.sh
```

已知还剩：

| 位置 | 值 | 判断 |
|---|---|---|
| 额度快照过期 | 86400 秒 | **合理**，就是 24 小时 |
| 各节的时间窗 | 86400 / 3600 / 300 | 合理，且写明了单位 |

**没有再发现像 `free > 200` 这样既无出处、又会导致错误建议的。**
但这条线值得每隔几轮复查一次 —— 尤其是新增检查项的时候。

## 9. 一条更普遍的教训

**写检查工具时，问自己两个问题：**

1. **这个阈值有出处吗？** 没有出处就说明它是拍的，而拍的数字会在
   环境变化后悄悄失效。
2. **如果这条建议被照做，会发生什么？** 第 64 轮发现的那条，
   照做的后果是「对一个 726 MB 的库做全表锁」。

**检查工具的建议会被当作权威执行。**它的错误比业务代码的错误更危险，
因为没人会去质疑一个「只读的健康检查」。
