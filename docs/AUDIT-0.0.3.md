# v0.0.3 验收与审计边界

本页记录审计边界；实际生产发布另见 [v0.0.3 发布回执](RELEASE-0.0.3.md)。版本号、测试数量和代码审查不能证明
“所有代码没有问题”或长期稳定性已经完成验收。

## 这一版解决什么

- 在现有工作台设置末尾加入「管家」「预警」，不另建 AI 服务。
- 管家使用 DeepSeek 与普通调用密钥，通过现有网关计量；只读工具涵盖资源、
  流量、三平台号池总量、预算、账本、版本、备份、证书、任务和安全汇总。
- 管家不能执行 shell、读取凭据、修改配置、重启、签到或无证据清零账务。
- 规则通知不等待 AI；采集、投递和分析独立运行。邮件记录发送前后状态，
  接受结果未知不重发；恢复与严重级别升级分别通知。
- 智汇管家邮件使用蓝白 HTML 与纯文本双格式，不再使用原“大肥鱼”口吻。
- 登录阻塞工作移出请求主循环，并发工作有界；失败计数持久化有序。
- 前置凭据检查、边缘限流与请求体保护、最小公开 readiness、JSON401 与实验入口退役
  纳入精确 Nginx 配置的隔离集成测试。
- 版本身份与发布目录绑定；发布/兼容回退验证不恢复历史业务数据。

## 如何区分证据

| 证据 | 能证明 | 不能证明 |
| --- | --- | --- |
| 单元与契约测试 | 对应逻辑及边界 | 真供应商、线上链路或长期 SLO |
| 私有 Linux 全量门禁 | 冻结源码在受限 Linux 中通过原严格测试 | 宿主运行时已等价、生产已切流 |
| 精确 Nginx site 集成 | 私有 TLS、真实会话/ASGI、合成 provider 与真实账本路径 | 完整生产 nginx 主配置、付费推理 |
| systemd 沙箱试验 | 实际可信启动链、降权、目录保护与中断恢复 | 生产新单元已安装或真实 SMTP 已发 |
| SMTP accepted | 发件服务器已接受这一封邮件 | 实际进收件箱、未进垃圾箱或用户已读 |
| 只读平台探针 | 对应探针在该时刻的结果 | 该平台所有模型可用或当前账号有推理权限 |

本次浏览器工具被工作设置禁用，不使用旁路浏览器冒充视觉验收。
源码内 UI 契约、TypeScript、静态资源闭包和真实 API 路由测试分别保留，
不能合并称为真实手机或全部页面像素级验收。

## 仍然需要独立闭环

1. 公开红包仍保持会话闸门，设备绑定领取回执、存储加密和过期销毁未完成，不能直接开放。
2. 历史用量缺证据仍为待核对；保留额度不是实扣，不以清零积压作为账务正确证明。
3. 离机恢复点、独立保管解密身份、干净主机全服务冷恢复和 RTO/RPO 演练仍待完成。
4. Manager 的 Docker 权限、上游容器非 root、systemd 覆盖层归并与引擎供应链仍待独立治理。
5. 单 worker 限流不等于多节点共享限流；新的源码不冒充复现历史原始前端提交。
6. 真实 DeepSeek 计量和工具、SMTP 接受已有回执；入箱、受控恢复、长期观察及生产回退演练仍需独立验收。

新告警链验收前保留旧通知。代码回退必须继续执行已有角色和日配额规则，
不恢复旧用户、账号、密钥、额度、撤销状态或账本。
