## 重要行为约定

- 停用平台：未获平台授权仍是 `403 platform_not_allowed`；已有历史授权但平台停用为 `503 platform_disabled`。
- 抓包开关：`enabled` 必须是JSON布尔值；字符串等不再隐式转换。旧响应字段保留，新增 `desired/effective/effective_scope/pending/blocked_reason/propagation_seconds`；有效状态范围是当前实例。
- 脱敏：统一使用现有明确规则；历史抓包内容只在读取/导出投影中处理，没有批量改写磁盘记录。
- 发布：静态入口原子切换前先准备资源；HTTP200还需内容与摘要正确。退出码0表示本轮必需检查通过，不代表已经证明零中断。
- 审计：管理写、拒绝与异常应可归属；普通成功轮询不应制造永久哈希链写放大。
- 版本：`VERSION` 为产品版本唯一输入。新版本或受审查源字节改变时记录为 `source-candidate`，实际构建SHA在打包时写入，构建成功也不等于生产已部署。同版本且源字节未变化的刷新保留既有构建身份。

## 回归与复核

新增并登记的行为回归：

- `test_security_audit_hardening`：权限矩阵、解析前体积限制、限流容量/过期、流式持久化脱敏、开关竞态。
- `test_audit_identity_platform_boundary`：真实ASGI审计、最小身份、停用平台的零上游副作用、准备失败与422错误形状。
- `test_audit_deploy_failure_paths`：临时目录中的真实shell、假curl/systemctl；复制失败、错误状态、旧页面、摘要冲突、并发锁与可捕获中断回切。
- `test_ci_required_gates`：必需检查缺失、失败和跳过都会使命令与结果文件明确失败。
- `test_version_candidate_provenance`：升版本清除旧构建/部署证据，同版本刷新不伪造新来源。

`test_platform_policy` 和 `test_v12100_trae_native` 修复后从历史例外清单移入门禁；没有通过扩大例外清单隐藏新失败。与默认停用平台无关的协议测试，显式启用合成平台来验证授权和转发合同。

本地应使用隔离临时数据、模拟上游和固定依赖。Linux CI继续在无外网网络命名空间中运行后端套件；测试进程不得读取生产账号或调用真实供应商。实际执行结果以对应提交的CI记录与 `ci-validation-summary.json` 为准。

```bash
python3.12 -m venv .venv
.venv/bin/pip install --require-hashes -r server/requirements.hashes.txt
.venv/bin/pip install --require-hashes -r tools/requirements-ci.txt
npm --prefix web ci
```

具备权限的Linux CI runner可使用已有隔离方式执行完整门禁：

```bash
sudo -n unshare --net env ZH_CI_NET_ISOLATED=1 .venv/bin/python tools/ci_regression.py --require-frontend --require-static
```

上述为CI/独立开发环境命令，不是生产维护步骤。前端还应执行 lint、typecheck、静态导出与依赖检查；shell发布脚本使用故障替身验收，不能在生产直接运行来“测试”。
