# Python 依赖版本审计 — 2026-11-15

**结论：关键依赖的版本都在各自已知问题的修复线之后。**

**但这份审计的边界必须先说清楚**（见第五节）：它是**按已知 CVE 逐项手工核对**，
不是全量扫描 —— 这台机器上**没有安装自动扫描工具**。

---

## 一、审计对象

| 项 | 值 |
| --- | --- |
| 生产依赖总数 | **34 个** |
| 运行环境 | `/opt/workbuddy-manager/venv`（独立虚拟环境，不污染系统 Python） |
| 关键包（有 CVE 历史的） | **15 个** |
| 自动扫描工具 | **未安装**（见第五节） |

**为什么只核 15 个**：全量 34 个里有十几是纯传递依赖（`sniffio`、`typing-extensions`
这类），历史上没有 CVE 记录。**把力气放在真正出过问题的地方。**

## 三、有更新但没升级的包

`fastapi` 当前 `0.141.1`，上游已到 `0.163.1`；另有 `anyio`、`certifi`、`click`、
`httptools`、`idna`、`psycopg` 等有新版本。

**没有升级的理由**：

- 这些更新**不包含针对已披露问题的修复**（关键包都在修复线之后）。
- 主版本跨度大的升级（`fastapi` 0.141 → 0.163）**会带来行为变更**，
  而当前服务在跑、有 99%+ 的成功率。
- **「有新版」不是升级的理由，「有非升不可的理由」才是。**

**什么时候该升**：某个包越过修复线、或需要它的新能力时，**单独升那一个并单独验证**，
不做「一次升一批」。

## 四、这份审计没做的事

- **没有实际执行漏洞扫描**，是按已知 CVE 清单人工核对。
- **没有核对每个包的完整 CVE 数据库**，只核了有历史记录的那些。
- **没有验证传递依赖的传递依赖**。

**这三条都是真实的盲区**，不是免责声明。它们意味着：**「没发现问题」不等于「没有问题」。**

## 五、为什么没有自动扫描

这台机器上没有 `pip-audit` 或同类工具，而且**安装它会引入新依赖** ——
为了审计依赖而新增依赖，本身就是一次风险变更。

**更好的路径**：在**构建侧**（不改生产环境）生成依赖清单并送去扫描，
把结果带回来判断。**这件事还没做。**

## 六、维护说明

**升级任何一个依赖后，请回来更新第二张表** —— 尤其是 `h11` 那一行。
它现在是「刚好够」，任何低于 0.16.0 的回退都会立刻变成不安全。
