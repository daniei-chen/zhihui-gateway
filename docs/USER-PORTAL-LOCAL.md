# 用户工作台：不透支门禁、异常恢复与隔离备份本地候选 r5

## 源码预发布补齐

总台新增重置用户密码弹窗，确认后撤销旧会话与旧代次密钥，积分和账号保留；重置解除密码失败锁定，不接受用户名加数字等简单密码。用户端请求记录可逐页读取，每页30条；费用缺失仍显示待核实。恢复隔离状态同时禁止开通用户、重置密码和开启自动签到。

这些补齐进入 `v0.0.4-rc.1` 源码预发布候选，不代表已部署或用户计费调用已开放。后续历史章节仅作追溯，当前限制以[预发布说明](RELEASE-0.0.4-RC.1.md)和r5门禁为准。

## r5 收尾：发送保持关闭，不把估算当硬费用上限

本轮仍仅本地源码、合成数据、临时目录验证；没有读取生产备份、连接线上、部署或切换。

- 本地现有上游合同没有可强制执行的单次credit上限。max_tokens、余额快照、超时或主动断流均不能证明供应商费用不超过钱包。因此新增 `portalbilling` 源码级拒绝门禁，没有环境变量、管理按钮或配置绕过。
- 普通用户额度为0仍返回429“额度已用尽，请联系管理员赠送额度”；余额大于0但硬费用保障缺失时，在预留和发送许可双边界返回503 `portal_hard_cap_unverified`，不调用供应商、不冻结用户余额。现有管理员密钥的既有策略不变。
- **这不是已实现可用的硬预算调用**。它消除了当前候选继续发出无上限用户请求的路径；要重新开放，需要上游可执行且可核验的费用上限合同，或另行明确改变收费合同，不能靠配置打开。旧异常欠额与真实费用证据保留。
- `pool_enabled` 与 `dispatch_enabled` 分离：已有扫码、共享签到和admin赠送仍可操作；用户端明确显示费用保障缺口和调用未开放，不把有余额误报为可调用。
- 合成消费回归显式mock费用门禁，仅用于测试历史账本预留/结算；独立门禁测试不mock，覆盖Chat Completions、Responses、Anthropic流式/非流式均拒绝且供应商客户端调用0次。

### 请求级异常恢复

- 收尾阶段在所有归属的请求/流工作已返回后追加 `portal_request_ends`，绑定request_id、owner_id、key_id、worker，不能用仅有HTTP日志、终帧或TTL替代。
- unknown请求若有匹配结束凭证，可在服务worker仍存活时由超级管理员凭供应商证据核对；没有凭证时仍要求worker明确退出。结束凭证不代表费用0，不自动解除冻结。
- 写结束凭证失败保持冻结；其他请求的凭证、错误用户/密钥/worker不认可；仍在途状态一律拒绝。原spool/死信/迟到费用冲突门禁不变。
- 三协议的非流式客户端进入/退出失败、流式等待响应头时的清理失败、响应/迭代器关闭超时或异常，都标为清理未确认，不生成结束凭证；后续一次清理成功不清除先前疑点。结束凭证仅代表网关拥有的工作已经收尾，不代表供应商已停止计费，人工核对仍必须有费用证据。

### 双库与凭据离线隔离备份

新增离线模块 `server.portalrecovery`：只接受显式绝对路径，无生产默认目标、无网页恢复入口，不使用压缩包解压，不做原地替换。

- `snapshot` 要求显式offline-confirmed：操作者必须先停止全部Manager与引擎写者。工具额外核验worker OS锁，主库→用户库持有SQLite写锁，用SQLite backup复制含WAL的双库；身份、公共/独立凭据、spool/死信/处置凭证同份清单，前后指纹变化即失败且不写完成清单。
- 校验文件类型、重解析点/符号链接、大小/数量、SHA256、SQLite完整性/外键、跨库密钥哈希归属、账号凭据UID、冻结分摊和余额不重复。文件清单SHA256由snapshot返回，必须独立保存；verify/restore要求这个可信摘要，不能只信包内可一起修改的清单。
- `restore-quarantine` 只接受不存在的新目录，拒绝已有目标与源目录重叠。复制前验证、复制后逐字节校验，再设置隔离标记，禁用主库全部调用密钥/管理Token、撤销两套旧会话/扫码、关闭自动签到，将reserved/forwarded改unknown，删除旧请求结束凭证，并将凭据封存在 `quarantined-credentials/`，常规auths目录保持空。
- 恢复隔离状态禁止调用、扫码入池、新赠送、签到、自动恢复和人工改账。历史快照可能遗漏快照之后的消费，**绝不直接把旧余额作为可用线上额度**；必须另行外部对账、恢复有效凭据/角色与显式发布验收。本工具没有一键解除隔离或覆盖生产入口。
- 恢复中途写盘失败可能留下尚未完成隔离的半成品目录。只有完成全部步骤才写 `RESTORED-QUARANTINE.json`；没有完成标记的副本严禁启动，也不能把目录存在当作恢复成功。工具拒绝向半成品目标重试覆盖；本轮不宣称恢复过程是断电原子部署。
- 目录含密钥材料：文件0600、目录0700意图仅在支持POSIX时有效；Windows ACL需另行治理。快照没有自动加密、异地备份或定时任务，不能提交Git或公开构建。工具只验证本版本兼容schema，不宣称支持任意历史版本迁移。
- SQLite锁和二次指纹不能证明不遵守约定的外部引擎停止、也不能发现凭据被改回原值的所有情况；offline-confirmed是必须由操作者履行的前提。Linux断电/真实跨进程SIGKILL仍未验收。

命令结构（文档示意，本轮没有对真实数据执行）：在 `repository/manager` 下用 `python -m server.portalrecovery snapshot`，逐项提供 `--main-db`、`--portal-db`、`--users`、`--auths`、`--isolated`、`--spool`、`--destination` 绝对路径及 `--offline-confirmed`；用 `verify --source ... --manifest-sha256 ...` 校验；用 `restore-quarantine --source ... --destination ... --manifest-sha256 ...` 仅恢复全新隔离目录。不要将真实目标路径复制到试验命令。

本地测试覆盖正常配对恢复、源不变、旧余额隔离、活worker/写锁拒绝、损坏/多余文件/清单穿越/清单与数据一起篡改拒绝、复制中凭据变化不形成完成快照。后续仍需Linux隔离和真实上游费用合同验证，不能上线。

## r4 不做信用或透支，仅admin可额外赠送

用户明确取消信用额度/未来签到预支方案；未实现信用额度、借款、循环授信或未来签到还款。

- 可消费积分为0时，网关429错误与用户页面提示“额度已用尽，请联系管理员赠送额度”。余额空时不发送模型请求，不自动补100或1000；进行中/费用未知冻结仍显示其真实原因，不能伪装成额度不足来解除。
- `/members` 用户卡片新增“赠送积分”，仅用户名 **admin**、角色 **admin** 的超级管理员本人会话可操作；后端身份依赖和提交授权代次再次核验。普通account_admin、其他名字的admin角色、viewer、用户密钥及管理API Token均不能赠送，同源校验保留。
- 赠送是用户钱包的实际积分批次，不绑定扫码账号，不增加账号数，不增加今日签到数，也不代表向供应商充值。管理员确认公共池承载能力后才能实际运营，赠送本身不改变上游余额。
- 赠送金额大于0、最多6位小数、单次最多100万积分；默认有效期30天，总台可选1至365天。有效期从首次成功入账起算；重试不延期。每日签到仍按原规则最多30天，互不改写。
- 赠送独立表、消费分摊、过期、失败归还、unknown冻结和原有账号积分一同按最早到期批次处理；无需伪造账号/UID或改老表的NOT NULL约束。
- 赠送action_id幂等，同一标识改用户/金额/有效期/原因拒绝；加分与事件/操作者/原因/有效期同事务提交。事件失败整体回滚，不出现加了分但无流水。
- 用户可见“管理员赠送积分”到账和到期流水，总台可见赠送原因及admin操作者。赠送不消除未知冻结、不抹去历史真实超额费用；既有超额异常仍需核对/明确处置，不把历史风险转换为可用信用。

本轮仅本地临时数据验证，没有实际发放生产积分、上线、连接或切换生产。r3的备份恢复/Linux联调等未完成门禁继续保留。

## r3 总台处置（优先于下方历史说明）

继续仅在本地源码、临时数据与合成预览实施；没有发布、切换、重启生产或真实供应商调用。

- `/members` 新增“积分异常与欠额处理”：费用待核对、用户欠额、处置记录，各自每页30条。总台用户摘要同步显示冻结与欠额。
- 人工费用核对仍只允许 unknown 且所属worker明确已退出；不能证明退出、尚在预留/发送阶段、同机进程存活一律禁止。前端显示禁止原因，后端再次核验，不提供强制解锁。
- 只要全局回执spool中有未重放文件、未处置死信、不可读取目录，或原已使用spool丢失，人工费用核对保守关闭。核对时按主库→用户库顺序锁定，避免与主库重放并发。迟到真实回执与人工金额/归属冲突时拒绝重放并保留凭证，不静默覆盖人工结果。
- 欠额有两种明确处置：`repay` 用该用户已入池、未冻结、未过期的积分按最早到期顺序抵扣；`waive` 由超级管理员明确豁免。两者均不增加积分、不修改原调用/供应商费用，也不动其他用户的钱包。
- 欠额处理带随机action_id和expected_units：原请求重试幂等，换内容复用标识拒绝；其他管理员已处理或新欠额到达后，旧表单拒绝。欠额、批次扣减、分摊、事件与审计记录在用户库同事务提交，审计写失败整体回滚。
- 操作仅超级管理员本人会话、同源请求、提交时授权代次复核。必须填写8至500字原因与凭证说明；页面提醒不要粘贴密码、Token或完整授权。凭证说明只给总台，不给普通用户页面。
- 表单展示和账本概览保留6位小数；0费用也要证据。确认勾选、提交中禁重复、提交失败锁定原内容并使用原处置标识重试；余额与欠额是不同的账，不把豁免显示成积分赠送。
- 用户端只见自己的抵扣/豁免流水标签及余额/欠额；unknown仍存在时，即使欠额清零也不解除冻结。

仍需完成Linux真实崩溃/权限、多写者及运行引擎配置门禁、双库凭据备份恢复/迁移、真实供应商奖励证据和单次硬费用策略；本轮没有把这些标为完成。

## r2 最新约定（优先于下方 r1 历史说明）

本轮仅修改本地源码、临时数据库与合成预览。没有连接生产、调用真实模型/扫码/签到、部署、重启或更改线上配置。

- 用户贡献的 WorkBuddy 国内个人账号加入默认公共池；请求不绑定贡献者账号。供应商实际选择的账号与钱包扣费归属完全分离，按请求密钥的明确归属扣用户自己的钱包。
- 用户端服务端白名单仅允许 `deepseek-v4-flash`、`deepseek-v4.1-flash`、`deepseek-v4-pro`，支持 `cn:` 写法。白名单是源码约束，不是页面隐藏；请求名与映射目标双检。禁止 global、Qoder、Trae、自定义上游与任意别名。实际在线目录未连接确认，不保证这三个型号当前均可用。
- 新增密钥生成/列表/撤销，明文只返回一次，不写浏览器存储；每用户最多5个有效密钥。新密钥 max_ips=0、ip_allowlist=[]，本轮不增加IP限制，也不改现有全局安全配置。
- 用户停用或密码重置撤销会话以及旧代次密钥。source=`portal-v1` 与密钥创建同事务提交，先禁用再绑定、最后激活；绑定失败的残留密钥不能退化为普通无限额密钥。每次解析/鉴权与发送许可重新核验用户代次和密钥归属。
- `WB_PORTAL_PUBLIC_POOL_ENABLED=1` 是进程启动级显式候选开关，默认0。已登记启动配置合同，但未写任何部署环境文件。关闭时密钥不进入调用链、账号不发布到引擎目录。

### 公共池与签到边界

- 初始余额/到期时间核实后才允许发布。未入池的初始/签到积分可以显示，但不计入调用可用额度；页面分别展示待入池和可调用数量。
- 公共池发布使用临时完整文件、fsync、同目录原子 no-clobber 硬链接，不覆盖已有文件，包括其他文件名下的相同UID与 disabled 文件。发布意图先落SQL，文件发布后SQL失败可通过随机 publication 标记恢复自己的文件，不认领其他管理员资产。
- 发布后用户端只读取同一份公共池凭据，不再将独立副本回写到引擎。引擎或总台续期写入的新凭据会被下一次用户操作读取。用户端不刷新/重登覆盖共享凭据；即将过期时提示总台或引擎续期。
- 原总台通过 Tencent 客户端发起的用户账号签到，转入同一 account/day SQL 执行权。用户/代签/自动任务共享状态；总台账号列表合并已签到状态。
- **发布前要求引擎 `schedule.checkin_enabled` 显式为 false**：引擎自身调度器无法参与本账本的SQL互斥。只检查文件配置不能证明正在运行的引擎已应用；正式启用前必须核验有效运行配置与全部写者已停。未更改当前开关。
- 公共池消费会影响签到前后余额差，无法完整证明净增100时仍待核对、不猜赠额。这会少入账，不会为了体验多发100。

### 消费账本

- 不编造模型定价；按上游真实 `usage.credit`（有限、非负、最多6位小数）结算。Chat Completions、Responses、Anthropic 共用预留、发送许可与终态记账。
- 首版单用户一次一个计费请求，多个密钥共享锁；保守冻结全部已入池、未过期可用批次。返回可靠完整终态与费用后，按最早到期批次扣除，余款沿原到期时间归还；请求期间已到期的余款直接过期，不续命。
- 发出前确定失败可释放；发送许可已落盘后的缺usage/缺credit、断流、取消、进程崩溃等保持unknown，不用15分钟TTL释放，也不因积分超过30天而解除费用未知阻塞。
- **这不是供应商硬费用上限**。没有可靠价格表或上游可强制的积分预算时，单次实际费用仍可能大于余额。超额记独立欠额，暂停后续请求；不挪扣其他用户钱包，不悄悄抹掉超额。
- Manager主库终态回执与请求日志同事务；独立用户库用幂等outbox应用，不宣称跨库原子。主库失败走既有spool，重放再恢复钱包；用户库应用失败则保留冻结，后台重试。未知费用不自动变0。
- 超级管理员可用 `/api/portal-admin/wallet-pending` 查看待核对；resolve接口要求金额、原因和证据说明，并且所属worker已明确死亡，不允许仅凭租约超时释放。人工对账和欠额UI已在r3补齐。

### 发布前仍需完成

- Linux真实权限、跨进程文件发布/引擎热加载与运行签到开关验收，受保护的双库/凭据恢复合同与版本化迁移演练。
- 明确供应商真实额度/有效期/到账证据，验证并行池消费下签到入账，真实扫码/续期/调用试运行须单独授权。
- 共享凭据现有总台与引擎之间的并发续期合同未重构；r2只避免增加第三份会反向覆盖的凭据。
- 请求/用户/积分历史进一步分页扩容，决定可靠的单次最大费用或可承受超额策略。当前不能作为已通过上线门禁的成品。

## r1 历史实现说明（r2 已替代其中“隔离不入池、不签发密钥”部分）

本批只扩展本地源码，不发布、不连接生产、不迁移现有管理员或公共号池。

## 入口与身份

- 用户端 `/portal`：独立用户名/密码登录，独立 HttpOnly/SameSite=Strict 会话，与管理 Cookie、管理 API Token 互不通用。
- 总台 `/members`：保留现有布局与权限，仅超级管理员本人会话可开通、停用用户、代签和设置自动签到。
- 首版不开放公开注册。管理员创建的普通用户不会写入现有 users.json，也不会得到全池读取权限。
- 用户请求明细只按明确 key_id + key_hash 归属查询，不按名称、assigned_to 或来源 IP 猜归属。

## 存储与调用边界

`DATA_DIR/user-portal.sqlite3` 保存用户、账号归属、签到执行权、积分批次及流水；凭据在 `DATA_DIR/user-portal-auths/`，文件排他创建/原子替换并设 0600。目录与文件不能放进 Git 或公开构建产物。生产接入前必须纳入受保护备份与恢复合同。

不改 Manager 主账本 schema、已有密钥和管理员权限。账号凭据不写入现有引擎 watched auth 目录，**暂不并入公共号池，也不签发可调用密钥**。

因此这不是完整可用的额度转发系统；只有积分入账/到期与两端操作闭环。用户专属选池或公共贡献池、请求预算预留、按最早到期批次扣费、语义完成结算与未知费用处理仍须单独实现。请求列表入口存在，未绑定调用密钥时真实返回空，不伪造请求。

## 账号与签到

- 首版只接 WorkBuddy 国内个人账号，不冒充 Qoder、Trae、国际版均有每日100的业务合同。
- 按 platform + realm + provider_uid 唯一绑定，同账号重新扫码不重复初始入账，也不更改归属。既有管理员池中的同 UID 拒绝认领，等待管理员核对，不自动转移历史资产。
- 首次授权不自动签到，先查询完整余额/到期明细，避免初始余额包含当天100后又加100。
- 初始余额若金额、到期时间缺失或总额不一致，保持 pending，不能当成0或已到账；可重新核实。
- 用户、总台代签、批量和自动任务共用数据库中 account/day 执行权。已成功、进行中或未知结果不由 TTL 自动重派；不同进程同日也不能重复获得执行权。
- 明确的签到成功响应，加上前后完整余额净增100，才生成每日批次。10001“已签到”只同步状态，不重新给100。仅凭余额变化无法证明的情况留待核实，不承诺已完整识别供应商奖励批次。
- 每日批次沿用上游到期时间，且最晚不超过本次领取开始后30天；初始余额不重新延长到期。
- 签到已成功但余额读取失败，保留成功待核实回执；“核对到账”只查询，不再次调用签到。未知结果无自动重试或自动补发。
- 自动签到默认关闭，只有 BACKGROUND_JOBS 主实例运行循环；总台显式启用后才发起。账号授权即将过期时复用现有官方 refresh 客户端，保存前比较旧凭据，不能覆盖较新的扫码授权。

## 已知验收缺口

- 本地夹具和浏览器演示不等于真实平台扫码、签到到账或供应商条款/授权验收。本轮没有真实扫码、模型、邮件和签到。
- 前后余额差是保守校验，不是完整的供应商奖励ID账本；外部并行使用/套餐重排/延迟到账可能保持待核实，不能据此多发额度。
- 尚无消费分摊、可调用密钥、选池、撤权与发送许可、跨日未知结算的端到端闭环，所有 dispatch_enabled 固定为 false。
- 分页和批量为有界首版：每用户最多100个绑定；用户一次签到50个，总台/自动一批100个；UI 初版只展示近100条积分事件及第一页请求。需要扩容时先完善分页，不删历史数据。
- 用户账号停用/重置密码通过 API 可撤销会话；首版管理 UI 提供启停，密码重置 UI 尚未补齐。
- 日志与页面中文优先；新用户页面尚未全语言翻译。
- 旧工作台原有账号页不混入这批隔离用户账号；请从新增“用户工作台”管理入口代签。这是避免现有池被新归属模型污染的暂时边界。
- 待核实/unknown/processing 的人工审查与凭证恢复 UI 尚不完整；不能盲目重发或清状态解决。
- 新独立数据库的版本化迁移、完整恢复及 Linux 真实文件权限/崩溃门禁尚未完成，不能直接上线。
