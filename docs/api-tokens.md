# 管理面 API Token

管理接口默认用浏览器会话（`wb_session` Cookie）鉴权。给脚本和 CI 用时，
可以另发**管理面 API Token**，不必把账号密码写进流水线。

## 两种凭证的定位

| 凭证 | 谁在用 | 能做什么 |
|---|---|---|
| 会话 Cookie | 浏览器面板 | 读写管理接口，按角色（admin / viewer）区分 |
| API Token | 脚本 / CI | 同管理员接口，但**不能**执行写操作以外的提权，也不能自助续期 |

## 一条必须知道的设计

**写操作要求「浏览器会话 + admin 角色」**，服务令牌不能写。

原因是历史问题：早期 qtgcore 的处理函数签名里没有任何授权依赖，而管理端原生同路径
处理函数都有管理员校验。这意味着只要拿一个已经登录的低权限会话、再加一个平台请求头，
就能对真实账号执行签到、改配置这类写操作。

修复后的判据是：写方法必须同时满足「Cookie 身份 role=admin」且「不是服务令牌」。
读方法（GET/HEAD/OPTIONS）行为不变，查看面板不受影响。

这条约束的直接后果：**用 API Token 跑 CI 时，读接口没问题，写接口会被 403**。
需要写就改用管理员会话，或走部署脚本里已有的内部通道。

## 泄漏了怎么办

- Token 存在 SQLite 的 `api_tokens` 表，可在面板「安全」页吊销。
- 令牌本身**不能**提权，也不能自助续期；吊销后立即失效。
- 所有管理动作都会写入审计链（`admin_events`，带前序哈希），事后可查。

## 与下游密钥的区别

别把两者搞混：

- **管理面 Token**：调 `/api/*` 管理接口，动的是面板本身。
- **下游密钥**（`wbk_xxx`）：调 `/v1/*` 反代接口，走的是模型调用，有独立配额、
  IP 白名单与模型白名单，明文仅在创建时展示一次。

给应用接入用的是后者，不是这里说的 Token。
