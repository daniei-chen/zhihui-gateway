# 管理面 API Token

管理接口默认用浏览器会话（`wb_session` Cookie）鉴权。给脚本和 CI 用时，
可以另发**管理面 API Token**，不必把账号密码写进流水线。

## 两种凭证的定位

| 凭证 | 谁在用 | 能做什么 |
|---|---|---|
| 会话 Cookie | 浏览器面板 | 读写管理接口，按角色（admin / viewer）区分 |
| API Token | 脚本 / CI | 同管理员接口，但**不能**执行写操作以外的提权，也不能自助续期 |

## 一条必须知道的设计

**写操作要求「浏览器会话 + admin 角色」**，服务令牌不能写。

原因是历史问题：早期 qtgcore 的处理函数签名里没有任何授权依赖，而管理端原生同路径
处理函数都有管理员校验。这意味着只要拿一个已经登录的低权限会话、再加一个平台请求头，
就能对真实账号执行签到、改配置这类写操作。

修复后的判据是：写方法必须同时满足「Cookie 身份 role=admin」且「不是服务令牌」。
读方法（GET/HEAD/OPTIONS）行为不变，查看面板不受影响。

这条约束的直接后果：**用 API Token 跑 CI 时，读接口没问题，写接口会被 403**。
需要写就改用管理员会话，或走部署脚本里已有的内部通道。

## 令牌绑定签发人的会话版本

令牌签发时记录签发人（`users.json` 里的那个账号）**当时的会话版本 `sv`**，鉴权时
要求它等于签发人**当前**的 `sv`。这条绑定是「吊销能收回令牌」的唯一保证：

- 改密码、改角色、面板上的「吊销会话」都只是 `sv + 1`；
- 所以这三种动作**同时收回该用户签发的全部令牌**，而不只是让他已登录的浏览器
  失效；签发人被删号，其令牌也立即失效（找不到签发人即拒绝）。

为什么必须绑：早期令牌与用户表零耦合，一次会话泄露可以被洗成**永不过期的
admin 凭据**——受害者改密码、踢会话、事后发现泄露都收不回来。绑上 `sv` 之后，
令牌不再是「独立于账号的长期凭据」，而是跟着账号安全状态走的凭据。

不传 `expires_at` 仍然允许，但**「不过期」只指不按时间过期，不等于不会失效**：
签发人任何一次 `sv` 变化（改密码、改角色、吊销会话、删号）都会让这枚令牌立刻作废。
强制过期只会静默断掉 CI 流水线，所以安全边界交给上面这条绑定来承担。

### 升级到本版本时

**升级会打断所有既有 API Token**：本版本之前签发的令牌没有会话版本，无法判断它是
否已经被别人拿到，因此一律拒绝（fail-closed，与不存在/已过期同样是 `401 未登录`）。
升级后请用管理员会话重新签发一枚，再在「安全」页删掉旧的：

```bash
curl -X POST https://<面板>/api/tokens \
  -H 'Content-Type: application/json' -b 'wb_session=...' \
  -d '{"name":"ci","scope":"admin"}'
```

## 泄漏了怎么办

- Token 存在 SQLite 的 `api_tokens` 表，可在面板「安全」页吊销。
- 令牌本身**不能**提权，也不能自助续期；吊销后立即失效。
- 更彻底的做法是「吊销会话」或**改密码**：它们会让该账号签发的令牌一并作废，
  这正是「会话泄露 → 洗成永久凭据」这条路被堵死的地方。
- 所有管理动作都会写入审计链（`admin_events`，带前序哈希），事后可查。

## 与下游密钥的区别

别把两者搞混：

- **管理面 Token**：调 `/api/*` 管理接口，动的是面板本身。
- **下游密钥**（`wbk_xxx`）：调 `/v1/*` 反代接口，走的是模型调用，有独立配额、
  IP 白名单与模型白名单，明文仅在创建时展示一次。

给应用接入用的是后者，不是这里说的 Token。
