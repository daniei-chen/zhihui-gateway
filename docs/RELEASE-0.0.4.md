# 智汇 0.0.4 发布候选与验收范围

当前文件先记录待验收候选，不能作为已经切换线上的证明。正式发布须绑定精确源码、签名产物、Linux完整测试回执与受信切换事务，完成后另行追加可核验身份。

用户确认尚未发布正式 0.0.4 时使用 0.0.4；因此本轮从未发布的 0.0.5 候选改为 `v0.0.4+portal.20261102.2`，不发布 0.0.5，也不移动历史预发布标签。上游固定来源和逐项取舍见[上游复核](UPSTREAM-REVIEW-0.0.4.md)。

## 功能与保护

- 用户端 `/portal` 与总台 `/members` 集成独立登录、官方扫码、账号数量、共享签到、初始余额核实、独立30天到期批次、admin实际积分赠送、密码重置和分页请求记录。
- 不做信用或未来签到预支，不增加IP限制。新用户计费调用仍拒绝发送，直到有可核验的上游单次积分硬费用上限；管理员原有调用策略不变。
- 受控实例关闭旧式包上传、删除和自助安装，已认证只读查看保持。旧更新器及历史误导性验签入口不恢复。
- 包结构检查使用有界临时流，不解压落地成员；检查压缩CRC和完整结束、归档结束、隐藏尾随归档、重复/路径别名、越界、链接/设备和大小/成员数上限。结构检查不授予发布者信任，不代替独立签名。
- 请求费用未知不自动释放；双库恢复只写全新隔离目录。代码回退不恢复业务数据库、账号凭据、密钥、会话撤销、额度或通知收件人。
- 用户端使用专用 `sk-portal-` 密钥格式，签名在用前驱只接受原有普通/历史格式，因此旧代码即使忽略用户钱包来源也不能将新密钥当成普通调用密钥；新代码仍核验来源、哈希、归属与会话撤销。受控回退另检查所有保留的用户密钥，不自动退回不理解钱包的旧代码。现有管理员密钥格式不变。

## 发布约束

首页和原版登录不随本次控制台升级改版；引擎镜像、容量与IP策略保留。公共池贡献开关默认关闭，自动签到默认关闭；不得为发布新页面顺手改变运行中引擎的独立签到配置。

先前 0.0.5 诊断候选的隔离 Linux 全量结果为 4193 通过、9 跳过、3 失败，未签发成功回执、未切换生产。失败涉及部署包缺少退役验签入口及旧 Compose 测试误走受控更新拒绝路径；本轮修复后须以新的 0.0.4 精确产物重跑。完整门禁、实际宿主发布器同版本坏签名/闭包/激活失败演练、当前状态兼容与切换后核验均不能用诊断候选替代。只有通过后才可切换与标为GitHub正式版本，失败保留现场并停止推进；不得刷新旧失败基线或忽略失败放行。

`0.0.4-rc.1` 为历史源码预发布，不移动其标签。既有完整审计工作包不因产品发版全部关闭。
