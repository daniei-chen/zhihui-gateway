# 连接账号，不连接错平台

智汇的账号授权由 Manager 显式分流。平台不是界面装饰，国内／国际也不是
只换一个标签：授权入口、状态查询、账号归属与完成提示必须一致。

## 当前能力

| 平台 | 国内版 | 国际版 | 完成方式 |
| --- | --- | --- | --- |
| WorkBuddy | 支持既有授权 | 支持既有授权，新号可选注册地区 | 官方页面授权，Manager 查询结果并保存 |
| Qoder | `qoder.com.cn` | `qoder.com`，引擎版本值为 `intl` | 官方设备授权，Qoder 引擎查询并保存 |
| Trae | 当前 aiwork 引擎支持 | 当前引擎未接入，明确拒绝 | 官方页面授权后粘贴本次 loopback 回调 |

授权成功只表示授权信息已保存。账号是否启用、是否在调度白名单、积分与
冷却状态仍以各平台账号列表和上游运行态为准。尤其 Trae 的授权保存与
`pool_list.enabled_uids` 是两件事，不能凭 OAuth 返回值宣称账号已经参与调度。

WorkBuddy 注册地区、出口线路和账号分组不自动套用到其他平台。不支持的参数
明确返回冲突，不默默忽略，也不回退到 WorkBuddy。

## 小窗与二维码

“前往平台授权”优先打开独立小窗。小窗被拦截时，普通新标签链接仍可用。
供应商页面与智汇隔离，`window.opener` 置空；智汇不读取跨域窗口地址，
不收集供应商密码，也不把一次性授权链接作为公开分享内容。

WorkBuddy 与 Qoder 通过智汇自己的授权结果接口更新主页面。Trae 当前回调为
`http://127.0.0.1:17388/authorize`：如果授权页面运行在用户设备上，loopback
也属于用户设备，Linux 服务器不会因为展示了一个链接二维码就接收到回调。

服务器代管浏览器是另一种独立架构：必须由 Linux 隔离浏览器持有官方登录
会话、展示官方实际提供的扫码内容，并由同一执行环境接收回调。不能把手机
打开授权链接后的回调误当成服务器回调。当前未交付服务器二维码自动回调，
不安装全局浏览器插件、桌面远控或全局代理来伪装这项能力。

## 安全合同

- `/api/auth/start`、`/api/auth/poll`、`/api/auth/finish` 和 `/api/auth/cancel`
  要求真人管理员或超级管理员会话；服务令牌不能导入平台凭据。
- `admin` 首次迁移为超级管理员，其他已有用户迁移为仅能添加账号的管理员；
  此后由超级管理员明确创建或调整，两种角色不被重启重新覆盖。
- `admin` 可双向调整其他用户权限；角色实变撤销该用户旧会话，相同角色设置不
  重复撤销。新用户（包括新超级管理员）的登录密码至少 8 个字符，不要求纯数字，
  不限制为 10 位；非主账号重置同此规则，不转换／截断输入。现有密码不重写，
  主账号 `admin` 初始化／重置仍保持原强密码规则，API 密钥不缩短。
  密码长度不代表实际熵，须保留登录限流和哈希存储，不建议选择常见弱口令。
- 平台头、查询参数与请求正文互相冲突时拒绝。授权状态绑定发起人、平台、
  版本、账号授权代次和目标引擎；猜到其他授权状态也不能跨用户或跨版本完成。
- 内部授权代次涵盖用户名、角色、会话版本和密码摘要，由当前会话密钥计算。
  删除／同名重建、改密、改角色或吊销会话后，重新登录也不能继承旧授权状态；
  内部指纹不返回页面，不写入身份桥接断言。密码校验后的签发同样复验原快照。
- WorkBuddy 后台和前台共用单会话串行完成合同，并在每次后续 HTTP 请求前
  复验账号代次，包括获取 Token 后查询账号、查地区后提交地区的内部 await。
  本地凭据提交与用户撤权共用短时用户存储锁，不跨网络 await 持锁。
  已发出的上游请求无法撤回；已确认保存的结果保留真实证据，不假装操作未发生。
- 国内／国际参数在正文与查询字符串冲突时也拒绝，不再静默按其中一处发码。
- 查询可能有账号写入副作用，因此额外检查跨站来源，不能当普通公开 GET。
- Qoder 不自动重试会产生入池副作用的查询；成功结果在智汇短期缓存，
  不把同一个完成结果反复提交上游。
- Trae 当前引擎只有一个进程级 PKCE 槽位，智汇以数据库事务跨进程互斥。
  不能让另一位用户重新取链覆盖仍在使用的授权状态。
- Trae 回调必须匹配本次 trace、loopback 路径和指定的 HTTPS 交换域名，
  拒绝重复参数、旧 token 直传与任意 host，防止重放和 SSRF。
- 回调中的 `userInfo` 不决定落盘账号 ID。身份来自交换后的令牌，避免
  客户端文本把一份新授权写到另一账号名下。
- 授权开始、轮询、完成禁用透明重试。提交后超时保留“结果待核对”，
  不能把“不知道”改成“未保存”，也不立即重发一次可能已经完成的写请求。
- 一次性回调不写入智汇会话台账、审计日志、Git 或截图。API 仅返回必要的
  账号元数据，不返回供应商 access/refresh token。

## 测试与边界

后端：`manager/server/tests/test_platform_auth.py`。前端：
`src/three-platform/web/tests/authorization-browser-scenarios.cjs`。
覆盖三平台 × 两版本、实际 Manager 路由、权限、来源、参数冲突、过期、
回调重放／主机校验、错误脱敏、晚到响应、小窗隔离和手机可用性。

这些测试使用合成供应商响应，不代表已经由真人完成六种供应商登录。
真实授权需要用户本人操作，不代为扫码，不绕过登录、渠道或账号限制。
回退恢复代码与界面，不恢复旧账号库、额度或会话撤销状态。

### 仍待发布前关闭的恢复边界

- Manager 的状态事务可以防止并发提交，但 Trae 引擎 PKCE 是单进程内存值。
  当前 adapter generation 在 Manager 重启或重认证后失效，旧回调明确拒绝；
  尚无跨 Manager worker／重启无缝恢复的合同，不应部署为任意多 worker。
- `unknown`／在途完成结果不靠 TTL 直接删除。Trae 结果未确认会阻止新会话
  覆盖 PKCE 槽；需要受控核对与释放流程。当前没有一键恢复入口，不应通过
  删除 settings 行、恢复旧 DB 或重发授权码来绕开。
- Qoder 查询可能消费设备授权并保存账号。超时、丢响应及孤立在途查询显示
  `unconfirmed`，不自动再问；这不是“授权失败”或“账号没保存”的证明。
- WorkBuddy 既有后台轮询仍在进程内运行；本轮加了会话归属检查，但没有
  将它改造成持久化跨进程任务。服务重启后重新取链仍是明确边界。取消会清理
  本地凭据备忘与锁；无活动请求时的 TTL 回收仍依赖后续清理触发，未证明
  一个永久后台清理器。多进程的 WorkBuddy 串行与恢复尚未交付。

新角色和每日额度生效后，旧代码即使能读新数据库，也未必执行同样的授权与
额度规则。首次迁移必须排空全部旧 writer／helper；未经能力下限验证，不得
直接回退到旧版，不恢复旧账号库、计数或撤权记录来规避此限制。

服务器代管浏览器方案与原型见 [SERVER-ASSISTED-AUTH.md](SERVER-ASSISTED-AUTH.md)，
不因本轮 Manager 完整门禁通过而被当作生产可用功能。
