## 三、那条性能修复，我们已经有了

#439 说静态资源 gzip 后「单个 chunk 174 KB → 46 KB，首屏明显变快」。

**我们的 nginx 早就开着**：

| 配置 | 值 |
| --- | --- |
| `gzip` | on |
| `gzip_static` | on |
| `gzip_comp_level` | 6 |
| `gzip_min_length` | 1024 |
| `gzip_types` | 含 `application/javascript`、`text/css`、`application/json` 等 |

实测 `/dashboard/` 的响应**确实带 `content-encoding: gzip`**。

上游那条是它自己进程内做的，我们靠 nginx 做 —— **同一个目标，两条路径，结果一样。**

**所以这一项没有增量。**

## 五、不跟进 #436 与 #430 的判断

两个都是上游 Go 服务端的功能。跟进意味着改 `workbuddy2api` 源码、重打补丁、
重编译镜像、重走部署 —— **风险落在最不该冒险的那一层**。

而它们解决的问题目前都不是瓶颈：

- 密钥每日限额：现有总额度与积分额度已经能限制单密钥消耗
- 搜索透传：现有对话链路没有因此受限

**所以本轮不动。** 记录在这里，等真的需要时再评估。
