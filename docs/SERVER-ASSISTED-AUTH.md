# 原生智汇弹窗，真实官方验证

状态：设计与公开页面合同已取证，本地控制器与私有传输原型通过 46 项合成测试，
**尚未部署服务器浏览器或开放生产手机号代填**。
本设计不替代已实现的平台授权分流与粘贴回调兜底。

原型代码在 `tools/authorization-worker/`，没有 Manager 路由引用，也不随
Manager 的独立运行树打包。测试在 Windows 的新建浏览器上下文与 loopback
合成站点进行，不等于 Linux sandbox、真实扫码或短信验收。真实二维码提取、
Manager 传输层、原生弹窗接线和可发布的 Linux worker 均仍待实现。
新增的 JSONL broker 是仅接受固定 loopback 合成站点的私有实验模块，不是
生产 Manager 接口；没有启动器、HTTP／CDP 入口，也不能向真实站点发短信。

## 使用体验

“连接 Trae · 国内版”保留智汇冰蓝小窗，先选两种方式：

| 方式 | 智汇显示 | Linux 执行 | 需要用户做什么 |
| --- | --- | --- | --- |
| 抖音扫码 | 本次会话的官方二维码、有效期与刷新状态 | 独立浏览器打开 Trae 官方登录，进入抖音授权并等待回跳 | 本人确认协议，在抖音确认账号与授权 |
| 手机号 | 国家／地区、手机号、验证码与发送倒计时 | 在同一官方网页代填手机号，按用户点击发短信，再代填验证码 | 本人确认协议、触发短信并提交收到的验证码 |
| 人工验证 | 临时展开官方页面实时画面，清楚标出官方域名 | 保留原网页 DOM、iframe、Cookie 和设备上下文 | 本人直接操作该次官方验证，完成后收回画面 |

二维码来自实际官方登录页，不是把普通授权 URL 包成二维码冒充远程确认。
滑块／点选验证不重画、不 OCR、不自动求解，也不修改供应商 SDK 或伪造设备。
智汇原生的是外层对话框；验证内容始终是官方当前那一页的实时画面。

短信不后台自动重发、不批量请求。地区不默认为另外的平台或版本；初期仅
开放已核实的中国大陆手机号合同，其他区号不能只改显示文本便称已支持。
抖音可能要求绑定手机号、手机二次确认或其他页面，遇到新状态进入人工接管，
不凭一个二维码宣称扫码后必定完成。

## 数据路径

```text
用户本人
  | 智汇原生弹窗：选择方式、填手机号／验证码、亲手验证
  v
Manager：现有管理员会话 + 同源校验 + 一次性授权会话
  | 固定的有限命令；不接受任意 URL、JS、CDP 或 shell
  v
独立 auth-worker：低权限 Linux 用户／短命隔离容器
  | 每会话独立浏览器环境；有限域名；无生产文件挂载
  v
Trae 官方登录 -> 抖音或短信 -> 官方人工验证 -> 官方授权
  | 固定 loopback 回调；PKCE 与 loginTraceID 绑定
  v
Manager 一次性完成授权 -> 对应 Trae 引擎保存 -> 确认结果
  | 仅返回安全账号元数据
  v
销毁浏览器会话；刷新对应平台账号列表
```

现有 Trae 引擎只有一个 PKCE 槽位：代管浏览器与小窗／粘贴模式共享同一把
授权锁，不能各自发一条授权链覆盖对方。浏览器与回调监听器必须在同一网络
命名空间。不能将手机的 `127.0.0.1` 当服务器地址，也不把 17388 暴露到公网。
若 worker 不在引擎命名空间，必须使用明确的、受保护的一次性回调传递协议。

## 必须先通过的工程闸门

1. **能力验证。** 公开页面已观察到“抖音登录”“输入手机号”“输入验证码”
   和“获取验证码”。尚未确认抖音二维码实际形态、扫码后回跳与所有动态验证
   分支；未发送真实短信，未接受服务条款，未交换真实令牌。依此不能发布
   “两种方式已支持”的功能声明。
2. **身份与防串用。** worker 会话绑定管理员、平台、版本、Manager state、
   trace 与 worker generation；所有 frame/input/finish 操作都复验。过期、
   关窗、切平台、登出与撤销立即停止接收新操作，旧画面不能驱动新会话。
3. **有限代填。** 仅 `select_method / submit_phone / request_sms / submit_code /
   human_input / status / cancel` 等固定动作。所有输入长度、频次、状态合法性
   在 Manager 与 worker 两侧检查；不传任意 CSS/XPath、脚本或调试命令。
4. **真正人工验证。** frame 绑定不可复用的帧号、当前域名与视口；触摸／鼠标
   坐标限定在该帧。帧过期、刷新、跨域或 viewport 变化后拒绝旧输入，支持
   down/move/up 与取消收尾，不让残留按下状态污染下一次验证。
5. **保密。** 手机号、短信码、完整回调、Cookie、令牌、画面和二维码不进
   access log、audit payload、trace、HAR、磁盘截图、Git 或异常堆栈。接口
   `Cache-Control: no-store`，frame 不走 CDN；短命 profile 存私有 tmpfs，关闭
   清理。禁止在会话 token 或 URL query 中携带手机号与验证码。
6. **网络与资源。** 独立非 root 用户、有 sandbox、无 Docker socket、无 host
   网络、无任意内网访问。允许站点依真实导航清单逐个核实；同时限制下载、
   弹窗、会话时长、内存、CPU、进程数和帧率。当前约 4GB 生产机不能未经
   隔离 soak 和内存上限演练就运行常驻 Chromium。
   Playwright `route` 白名单只是导航辅助防线，不是内核出站隔离；DNS 重绑定、
   WebSocket、WebRTC 与未走 HTTP 路由的流量必须另行约束和负测。
7. **结果与恢复。** 浏览器进程退出、网络超时或完成请求丢失时显示结果待核对，
   不重复消费授权码、不伪报失败或成功。由账号列表与持久化结果核对后恢复，
   不是删掉“未知”台账求继续。发布、浏览器升级和关停都要验证此路径。
8. **供应链与回退。** 浏览器包与运行时固定版本、来源与摘要，独立构建和签名。
   功能开关默认关闭；关闭 worker 时原小窗／粘贴方式仍存在。回退代码不恢复
   历史账号、额度或已撤销会话。禁止通过反检测、代理轮换或挑战自动求解去
   绕过供应商的渠道限制。

## 上线次序

先做完全合成供应商站点的 Linux 隔离原型：扫码、短信倒计时、人工触摸、
回调、超时和销毁；然后以本人操作的受控账号验证真实供应商链路；最后才
开放控制台入口。首页演示如展示此功能，必须标为演示，不能把未交付入口
塞进实际账号连接流程。
