# 三个平台，一套智汇语言，不伪造一套上游事实

本轮对照公开 GitHub 固定提交，研究授权、候选账号过滤、在途计数、冷却、
持久化和页面状态的对应关系。不以 stars 代替工程验收，不直接将上游 main
覆盖生产引擎，也不把第三方项目描述当成官方接口保证。

## 已落实在授权修复中的机制

1. **按能力分流，而不是按皮肤分流。** Qoder 的 `cn/intl` 与控制台的
   `cn/global` 明确映射；Trae 使用自己的命令，不调用 WorkBuddy 的授权服务。
2. **授权生命周期有边界。** 开始、等待、完成、失效和待核对各有实际语义，
   未确认入池不报成功；切平台、关弹窗后的旧响应不能重新挂上定时器。
3. **副作用不透明重试。** 取链、Qoder 入池轮询和 Trae 完成不使用通用重试。
   结果未确认时保留台账，防止重放。
4. **统一品牌，不统一谎话。** 智汇标题、短提示和冰蓝组件共享；官方平台名、
   实际地区与能力限制保留。成功提示不再凭空承诺签到、积分或调度就绪。

## 接下来按证据验收的号池改进

| 项目 | 要解决的问题 | 验收依据 |
| --- | --- | --- |
| 就绪状态 | 已导入不等于在池、在池不等于可调度 | 页面状态与实际 candidate/selectable 谓词逐项一致 |
| 并发上限 | “全部忙时选最不忙”不一定是硬上限 | 过载时有界排队／拒绝；断流、取消和异常均释放占用 |
| 冷却分类 | 单次渠道校验拒绝不等于账号失效 | 区分渠道、模型限流、额度保护、凭据失效与人工停用 |
| 凭据持久化 | 原子文件替换不等于跨写者不丢更新 | token 更新与人工代理／权重修改并发时保留双方字段 |
| 未知积分 | 读不到不能显示为 0，也不能冒充实时余额 | 空值、真零、过期快照和未确认用量可区分 |
| 区域隔离 | 国内缺号不能偷偷转国际或别的平台 | 授权、模型、实际请求目标和账本归因矩阵一致 |
| 重试预算 | 重试可能产生多次供应商处理 | 三协议共享截止时间；有用量／输出证据不自动重放 |
| 发布与恢复 | 回退代码不能复活旧授权或退回用量 | 签名输入、精确前驱、实际回退／forward，不恢复旧 DB |

上游某实现的“保证请求不失败”策略不能直接作为智汇策略：例如全部账号忙时
超额选号，会破坏硬并发合同。稳定性需要有界失败、准确状态和可核对账本，
不是将错误藏起来。上述未标已落实的项目仍属于待验收工作，不以本轮授权修复
冒充全网关审计完成。
