# Trae → HTTPS → Linux：一次可撤回的到达实验

2026-10-30。独立实验已上线，**真实官方回调尚待用户本人验证**，不是正式自动入池功能。

## 从哪里试

1. 在同一个浏览器登录智汇，再打开 `https://zhihui.kaogong.art/trae-callback-test/`。
2. 先结束控制台其他正在等待的 Trae 授权，再点击“开始一次回调验证”。
3. 点击官方链接，由本人在 `www.trae.cn` 完成正常登录和必要的人机验证。
4. 官方若允许此目标，会回到智汇并显示“Linux 已收到匹配的回调”；随后点击“结束测试并释放授权”。

不要把完整回调、一次性授权码、官方验证截图中的敏感参数发给他人。反馈结果页的提示文字即可。
这里使用现有域名的独立子路径，不需要设备上的回调程序、额外 DNS 或修改原登录页。

## 证据边界

| 已验证 | 尚未验证 |
| --- | --- |
| Nginx HTTPS 路径可代理到 Linux 回环接收器 | Trae 官方运行时是否允许自定义回调目标 |
| 本人会话、角色、授权归属与代次检查 | 真实授权码有效性及兑换兼容性 |
| 重复、取消、过期、跨站请求被拒绝 | 账号入池与后续刷新 |
| 合成查询标记未出现在检查的 Nginx／服务日志中 | 全部浏览器／手机的 cookie 行为 |

接收器没有兑换／finish 能力：授权码与 userInfo 仅作内存格式检查后丢弃，不记录、不反射、不导入账号。
匹配 trace 只能证明本次链接的回调到达，不是密码学意义上的官方签发证明；正式接入仍需要正常兑换校验。
静态官方 bundle 会读取 `auth_callback_url` 并构造跳转地址，仅是值得试验的线索，不代替官方允许证明。

## 已部署的隔离边界

- 固定 `127.0.0.1:17388`，公网不开放该端口；仅专用 HTTPS 路径代理，关闭该位置访问／错误日志。
- 独立动态用户、零 capabilities、NoNewPrivileges；只读系统，应用数据／家目录不可访问。
- 网络仅回环、96 MiB 内存、16 个任务、20% CPU、最多 8 个并行请求与 8 个内存会话。
- 不开机启用，最长两天后停止；无持久化测试会话，不修改 Manager 代码或现有登录流程。
- 新建授权仍会使用既有 Trae 引擎的 PKCE 槽，因此不要同时从另一控制台窗口发起或兑换授权。
- 超长／畸形请求在 Nginx 路径匹配前被拒绝时仍受全站日志策略约束，没有为实验关闭全站日志。

## 验证与回退

Windows 与 Linux 各 10 项合成测试通过；Linux 使用 nobody 用户运行测试。

未代用户触发真实授权 start、登录、验证码、兑换、账号导入。
