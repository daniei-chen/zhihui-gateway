# v0.0.7 · 自用稳定性升级候选

发行构建：`v0.0.7+stable.20261105.1`。基线为 `v0.0.6+stable.20261104.4`，已在 2026-11-05 00:08 北京时间只读核实；正式上线与 GitHub 发布状态以独立验收回执为准。运维窗口及新增优化的完整边界见 [0.0.7 运维合同](v0.0.7-operations.md)。

## 1. 合入前面尚未发布的改动

- 原 6 条内置兼容规则加上 4 条 DSH 已验证规则，消除只在热数据库中存在的恢复缺口。
- 限定 `11128` 备用路径重试，两条路径都拒绝后结束；不继续账号轰炸、全局降级或重发同一路径。
- 归档 CLI 默认只读；导出需要 `--apply`，删除还要确认已校验的 SHA。数据集、水位、真实文件、manifest 与归档台账必须一致。
- v2 dispatch / provider attempt 与历史 attempt 分开，缺证据为 `null` 而不是 0；真实尝试时间线不编造每次扣费。
- 增加证据采集新鲜度、pending、oldest、conflicts；未采样或过期不冒充健康。
- 合入 unknown 分类、年龄和凭证存在标记。只增加核对能力，不自动核销历史未决。

## 2. 本轮新增

### Codex、Claude 与 DSH

兼容规则包为 `workbuddy-prompts-20261104.2`，共 11 条具名规则，另有有界字面模板变体（待随候选闭包签名）。Claude 补齐 `CLI tool`、直/弯引号与大小写，且旧热规则不会遮蔽新规则。匹配使用转义字面模板，不允许配置任意正则。

只作用于 WorkBuddy 的 system/developer 文本，不修改用户、助手、工具消息正文、工具参数 JSON、图片。保持幂等和即时关闭。Codex / DSH 既有已验证身份规则一并保留。

此处的“修复”是请求适配，不是供应商渠道授权；不能承诺未知模板永不触发 `11128`。拒绝仍是拒绝，账号可用性不因此被误改。

### 凭证续期竞争

- Go / Python 同账号并发刷新合并；单个等待者取消不取消已在进行的共享续期。
- 两端使用同路径 `.refresh.lock` 的内核锁；进程退出释放锁，不用“锁文件存在”判断进程活性。
- 锁内重读凭证，接纳其他写者已完成的新代次；旧代次和身份不匹配时拒绝覆盖。
- Go 保存时保留最新文件中的未知字段、代理、权重和大整数元数据；文件与目录按平台能力同步落盘。删除过的已绑定凭证不被后台复活。
- 同一次共享刷新失败只记一次账号惩罚；客户端等待取消不惩罚账号。
- 配置写入遇到刷新占用时快速失败并提示重试，避免阻塞异步事件循环；只读快照可继续读取。

锁是合作式协议，不承诺阻止不遵守锁的外部手工编辑。Linux 绑定目录的 UID、权限和崩溃行为仍是正式门禁验收项。

### 小预算与账号软偏好

对 DeepSeek 正数输出预算 ≤1024、没有显式推理控制的请求，不额外注入默认 thinking/high。**不强制关闭供应商原生推理**。显式 effort/thinking 优先；保留 token 参数别名翻译。

新增积分软下限和大请求滑动窗口分散策略，**默认关闭**。只将权威余额视为已知，不把未知余额当 0；若所有可用号都低于软偏好，仍回退到原可用池。小请求不因大请求窗口失去粘性。这不是财务预算或费用上限，也不替代区域、并发和账号健康约束。

### 自动归档与核对队列

- 不再由请求热路径直接删除 90 天日志，只通知后台工作者。
- 默认每 300 秒、每个数据集最多 200 行，使用独立 SQLite 连接、短写事务和空间下限。
- 导出、逐行 JSON 校验、文件/目录同步和 SHA/manifest/台账校验后，按具体归档行及当前内容一致性删除。水位不是删除凭证。
- 未决请求关联行不删除；导出后发生变化或后来才满足条件的行不会被误删。后台重新扫描可覆盖迟到变更。
- 未校验、坏归档、磁盘不足、写锁竞争保留原数据并报告异常；关闭自动归档不恢复直接删除。
- `/api/logs/clear` 改为 `409`，禁止绕过归档证据批量清空日志。
- 设置 → 系统新增只读分页核对队列和有界凭证视图；不会一键清零 unknown，不将其冒充钱包冻结。

### 模型目录与诊断

模型目录按区域合并并发构建，取消一个等待者不会取消共享构建；配置失效后旧任务不能回填缓存。新鲜度、缓存期限及已被替代状态显式返回。

新增 `python -m server.diagnostics --db ...`：只读、限定样本与执行时间，仅输出归一化元数据，不读取设置、账号密钥或原始请求，不发推理请求，也不以样本计数证明网关整体健康。

启动完成前等待一次真实就绪采样，避免依赖后台首轮调度时序而短暂返回 503；采样异常保持未知，真实数据库/账本故障或排空状态仍不放行。采样在线程执行，取消时等待阻塞工作结束再释放所有权，不复用上次生命周期的绿色缓存。

中英文 README 同步，并保留部署模板入口。文档打包按引用闭包核对，包含嵌套发行说明；嵌套链接不能因只取文件名而漏检。

## 3. 保留的紧急修复与不可变约束

### 智汇发布中心与旧升级器隔离

设置页不再保留旧式“全部更新 / 仅管理端”、网页上传安装或自动重建重启入口。产品、发行页、更新通知、关于说明与五种语言文案统一为智汇；发行说明链接不再跳到 WorkBuddy Manager 仓库。Web 端旧安装调用也已移除，旧 `/api/system/update` 对所有部署形态返回 `409 / trusted_publisher_required`，即使缺少 managed 标记也不会启动安装进程。

当前状态只读取独立的 `DATA_DIR/zhihui-release-status.json`。旧 `update-status.json` / `update.log` 不再被合并为当前版本或发布成功；GET 不会自动删文件。新回执必须匹配智汇仓库、schema 与当前 release_id，只接受有界阶段代码，不展示任意命令、URL 或原始日志；发布器报告不等于本页已经验签或验证就绪。

管理员可显式归档两个旧展示文件：先写私有副本并同步、逐字节验证和记录 SHA，再核对源文件未变后移出旧展示位置。锁存在、状态不明、进程存活或权限/存储异常均拒绝，不能用超时猜测旧进程已死。此操作不处理调用日志、账号、配置、密钥、当前发布回执或业务账本。

移除了旧页每 15 秒重复取版本、Docker 能力和日志的轮询；本地身份和回执并行读取，GitHub 检查独立进行，不再卡住本机版本展示。GitHub Token/镜像仅用于智汇发行元信息，不赋予安装权限。

旧目录、systemd 名、环境变量、浏览器偏好存储与协议标识保留兼容，不做可能打断运行的机械重命名；开源许可证和真实上游归属保留。历史非受控安装辅助库不作为智汇网页安装通道或上线工具。

`.4` 的 `portalwallet.py` / `portalrecovery.py` 从基线保留。取消用户侧挂起计费需要符合原有证据与等待条件，不能据此推断供应商零用量。已撤销历史密钥不误判配对备份的活动身份。

不从截断日志重建终身消费，不删除/重写不可变账本事件，不回灌业务库做代码回滚，不把未知进程活性当死亡，不把 SQLite commit 等同于 WAL 已 checkpoint。

## 4. 仍不支持 / 不处理

- 不实现高级 Responses 状态服务、后台任务、严格工具 schema 或串行工具保证；不支持的语义在消费前明确拒绝。
- 不新增售卖、补贴风控、费用运营工作台、媒体生成或 Rust 重构。
- 不修改弱口令、管理员、会话和权限；不上传异地备份。
- 不保证供应商不会变更风控；实际 Codex / Claude / DSH 模板仍须获准上线后做小流量验收。

## 5. 发布条件

完整测试回执、源文件哈希和 Linux ELF 身份由本地候选验收报告提供。Windows 平台差异、Linux 最终门禁、签名和现网验收分别记录，不互相替代。

只有用户明确批准后，才可在重新核对现网、配对备份、签名测试绑定和受控排空均通过的前提下切换；失败恢复旧代码/引擎，不恢复旧业务库。详见 [操作合同](../V007-OPERATIONS.md)。
