## 2. 硬编码中文：128 个文件里只有 1 处

第一次粗暴 grep 得到 **851 行**含中文 —— 但那几乎全是**代码注释**，不是用户可见文本。

写了脚本正确跟踪 `{/* ... */}`、`/* ... */`、`//` 三种注释（含跨行），
在字符串字面量内部不误判，重新扫描：

```
扫描 128 个 .tsx，去掉注释后仍含中文的行：1
  app/(main)/security/page.tsx:602
  {a.actor === '(无)' ? t('security.actorEmpty') : a.actor || '无'}
```

**这一处也基本无害**：

- 服务端返回 `'(无)'` 时 → 走 `t('security.actorEmpty')`，**已国际化**
- 只有 `a.actor` 为 `null`/`''` 时 → 显示裸的 `'无'`

要改就得同时改前面那个 `=== '(无)'` 的判断依据（那是服务端返回的字面量，规范 §2.2 明确不许改写上游原文），
改动面比收益大。**所以不改，只记录。**

## 4. 我犯的错：把「复数形式」当成「缺键」

第一次比较时我写了个 `flat()` 把所有嵌套对象拍平成 `a.b.c`，然后算差集。
结果报出 **`en` 缺 9 个键**：`format.minutes`、`credit.expiresInDays`、`metric.creditAmount` 等。

**看起来是个真缺陷** —— 英文用户会看到中文兜底。我差点就动手补了。

然后直接查了一下原始 JSON：

```json
// en.json
"minutes": {"one": "{n} minute", "other": "{n} minutes"}

// zh-CN.json
"minutes": "{n} 分钟"
```

**英文不是缺键，是用了复数对象。**

我的 `flat()` 遇到 dict 就继续递归，把 `format.minutes` 拆成了
`format.minutes.one` 和 `format.minutes.other` —— **`format.minutes` 这个键本身没被记录**，
所以在差集里显示为「缺失」。

**英文的复数处理比中文更完善。**我把「更完善」当成了「有缺口」。

### 这是同一种错误的第四次

| 轮次 | 表现 | 实质 |
|---|---|---|
| 19 | 查不到字段就以为没有 | 查询条件错 |
| 27 | 查不到记录就以为不存在 | 查询条件错 |
| 32 | `LIKE '/v1/chat%'` 查不到就以为没推理流量 | 查询条件错（应为 `/v1/chat/completions`） |
| 40 | `$?` 拿到的是 `tail` 的退出码 | 测量对象错 |
| **44** | **`flat()` 把复数对象拆开，误报缺键** | **测量工具错** |

**共同点：错的是测量，不是被测量的东西。**

已记在 `OPS-PITFALLS.md` 第十三条（查不到不等于没有）。这一轮是它第五次应验。
