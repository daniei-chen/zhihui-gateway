## 持续开放的工作

私有工程审计的 18 项持续验收事项中，语言入口范围已关闭，其他 17 项仍需独立证据。主要类别包括：

1. 凭据轮换及旧会话失效验证，不能用本地日志脱敏替代吊销。
2. 引擎原生 TLS / 加密依赖升级及真实 Linux 产物验证，不能用 OS 补丁替代。
3. 离机加密灾备和干净主机恢复，必须先确定合法目的地与密钥托管。
4. 支持版干净构建、完整供应链溯源与持续依赖治理。
5. 调度器 / producer / 备份 / 维护的共同协调、历史归档与失败补偿。
6. 长连接 / 长流 / 跨服务恢复、真实角色 / 设备 / 任务 / 引擎升级与模型长尾验收。

不为取得“全绿”而调低完整门禁、增加 skip、归零未知费用、修改既有限流或回退用户业务状态。

## 上线与回退

版本是否已上线应以服务器运行版本、受签名覆盖的源码提交和实际发布回执为准，不以这个文件、Git tag 或 README 为准。当前生产合同见 [PRODUCT-RELEASE.md](PRODUCT-RELEASE.md)。

受信后端、控制台与品牌静态资源分别具有回退合同，不是假想的跨目录全局原子发布。回退仅恢复代码/静态表达，不恢复旧数据库、账号授权、额度或会话撤销记录。生产私钥、原始事件日志、内部端点详情和个人资料不在公开仓库中。
