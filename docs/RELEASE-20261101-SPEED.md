# 智汇提速迭代 / 2026-11-01

候选 `v0.0.3+speed.20261101.1`。本文写入时尚未部署，不把隔离测试当作线上提速证据。

## 改动边界

- 三协议共用异步转发准备：JSON 序列化和预算/配置读写在线程运行；保留字节预留始终回到所属事件循环，按精确 64 KiB 块合并。
- 取消时等待工作线程结束才释放 body、密钥和预算租约；编码完成、发送前重新校验当前密钥，准备期间撤销的凭证不发往上游，未发送预算可释放。
- 不修改提示内容、压缩阈值、128 MiB 上限、总并发 60、大请求并发 16、384 MiB 保留字节预算或 WorkBuddy 镜像。
- 仪表盘仅读取当前分组的已登记/引擎余额快照，页面明确标注；实时积分仍可在账号页刷新。快照不是实时到账证明。
- 同账号、授权指纹及失效代的并发积分查询合并；更换授权或失效期间的旧查询不回填。余额快照更新串行事务保护，避免不同账号覆盖彼此。
- Qoder/Trae 的账号、池状态及模型读取按所选平台获取，避免一个平台等待另一个平台的统计；池列表失败不伪装成空池。无平台的全量聚合保留。
- 首页、登录页、账号、六把已分发密钥、用户权限、配额、收件人及历史账本均不迁移或恢复历史副本。

## 性能证据口径

新增 `request_performance` 仅保存执行 ID、协议、终态、有限阶段毫秒及字节数，不保存正文、响应内容、账号或凭据。明细保留 7 天，进程汇总通过受保护的 `GET /api/system/performance` 读取。

上传、JSON 解析、转发准备、编码、预算准备、传输槽位、HTTP 连接/TLS、请求发送、响应头等待、结算与预算收尾分别计时。`forward_prepare` 包含编码/预算，`transport_headers` 包含连接/发送/响应头，属于嵌套跨度，不能直接求和。

`first_useful` 是首个文字、推理或工具事件，不等于首个用户可见答案。传输时间仍是 Manager 到本地引擎的边界；要分离官方上游排队/prefill，仍需引擎级阶段证据。
