# 当前发布使用 Ed25519 签名

本文以前记录过继承组件取消离线签名的做法。该做法不适用于智汇当前受控实例；历史原文保留在 Git 历史中，不再作为可执行操作指引。

当前产品合同见 [产品版本、来源与安全升级](../../docs/PRODUCT-RELEASE.md) 和 [发版与签名](../../docs/release-signing.md)。

- GitHub 下载摘要（sha256）只核对下载字节，不能代替当前受信签名。
- 后端需要精确源码清单、Ed25519 签名、完整隔离测试和绑定输入/运行时的独立回执。
- 新代码、版本或 provenance 变化后必须重新测试；缺清单、签名或回执时阻断。
- 只能通过已安装的 root-owned 可信发布器切换生产，不从应用目录自我批准或裸重启。
- 前端和静态品牌资源走各自精确前身事务；代码回退不恢复业务数据库。

仓库中的历史安装模板与嵌套 workflow 只是参考，不是当前生产发布授权。
