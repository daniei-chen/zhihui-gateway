# K08 指标凭据与兼容发布（本地候选）

应用 `/metrics` 现在逐次鉴权，含静态页面 fallback 和子路径别名。
管理员会话和 admin scope 管理令牌可诊断；readonly/keys 令牌不能抓取。
采集器使用独立 `wbm_` 凭据，不能读取管理数据、修改配置或调用模型。
本机来源不会绕过鉴权。代理仍保留来源限制，不注入共享管理令牌。

优先设置 `WB_METRICS_TOKEN_FILE` 为服务用户可读的绝对路径，文件必须是普通文件，
POSIX 权限 0600，不允许软链。文件内容为 `wbm_` 加至少 32 字节安全随机数的编码，
仅末尾换行可被剥离；不得复用现有管理/推理凭据。应用不创建或输出该文件。
`WB_METRICS_TOKEN` 只作为不使用文件时的备选，不在日志/命令行/报告中记录明文。

发布顺序：

1. 清点所有实际采集入口，包括直连 7864、`/wb/metrics`、`/wb/api/metrics` 和 QTG 自身指标；
   区分不同应用凭据，不能把 Manager 凭据当成 QTG 凭据。
2. 在候选环境配置凭据文件和采集器的 `authorization.credentials_file`，以脱敏方式保留指纹。
   先检查采集器当前版本是否支持该字段；不支持则采用已核验的同等配置。
3. 应用发布前先部署采集器配置；旧应用忽略 Authorization，仍可抓取。
4. 应用和代理按已演练批次上线；所有实际别名匿名无指标、采集 200、管理端拒绝采集凭据。
5. 回读采集目标状态和告警，避免用 URL 的 2xx 当作采集成功。记录抓取耗时、DB 成本和失败重试。

轮换文件使用同目录新文件、设置所有权/0600、原子替换，然后同步采集器文件并 reload。
应用每次读取文件，无需重启。短暂不同步会使抓取失败，须在告警窗口内核验恢复。
如需双凭据无缝轮换，应另行实现有期限的双槽设计，当前不声称支持。
回退不得恢复匿名指标；若回退旧应用，必须保持代理来源隔离。

当前仅完成应用保护与本地测试。真实 Nginx 全别名、采集器集成和大数据库成本仍待验，K08 不关闭。
