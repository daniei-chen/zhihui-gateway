# K52 运维文档与遗留资产（清单）

## 目标

每个遗留资产都能回答：它是什么、谁在用、还能不能用、什么时候可以清理、清理前要保留什么。
"文件缺失/mtime 很老"都不是"可以删"的理由。

## 文档纪律

1. 每个 unit/脚本/定时器都有对应 README（用途、输入、失败行为、回退）；
2. 发布记录包含：release_id、commit、制品哈希、变更、回退路径（03 方案 §11）；
3. 手册随版本生成，不靠"某人记得"；
4. 清理必须留"归档 + 可取回记录"，不是 rm。

## 未验证

- 每个遗留目录的实际引用方（需要只读 grep + 进程/配置扫描）；
- 旧域名是否仍有外部客户端（需要访问日志统计）；
- 备份目录的保留价值（需逐个检查内容与时间）。
